# kv-ai-designation — P0 지정 기술 후보 실측

> **Feature**: kv-ai-designation
> **Date**: 2026-08-27
> **Question**: 서버 없는 정적 앱 안에서 "클릭 한 번 → 오브젝트 마스크"가 성립하는가. 성립한다면 어떤 후보로, 몇 MB·몇 ms·어떤 정확도로, 그리고 그 마스크는 프로젝트 파일에 담기는가 (Plan §1.4)
> **Verdict**: **성립한다.** MediaPipe Interactive Segmenter v1(magic_touch) — 첫 사용 17.2MB, warm 0.54~0.65초, 마스크 IoU 0.84~0.98, 저장 0.9~3.5KB. 모델 없는 경로(플러드 필·COCO 디텍터)는 캐릭터에서 무너지고, 밝은 영역 검출은 **광원 자동 후보**로만 유효하다. 게임 아트 정확도의 최종 판정은 요청자 실소재로 남는다(§6).

---

## 1. 무엇을 물었나

kv-object-animation은 지정을 드래그 사각형까지 배송하고, AI 경로를 다음 사이클로
미뤘다([Plan §1.4](../01-plan/features/kv-object-animation.plan.md), D-01·D-02).
그 사이클의 종료 시점에 요청자가 두 가지를 더 요청했다
([report §5](../04-report/kv-object-animation.report.md)):

1. 클릭 하나로 캐릭터 같은 오브젝트를 지정
2. 이펙트를 걸 만한 오브젝트를 AI가 먼저 찾아 제안

이 스파이크는 Plan 착수 전에 **네 후보를 같은 소재·같은 클릭으로** 비교한다.

| # | 후보 | 성격 |
|---|---|---|
| A | MediaPipe Interactive Segmenter (magic_touch v1 / v2) | 클릭 → 마스크, 온디바이스 |
| B | 플러드 필 (모델 없음) | 클릭 → 색 유사 영역 |
| C | MediaPipe Object Detector (EfficientDet-Lite0, COCO) | 자동 박스 제안 |
| D | 밝은 영역 연결성분 (모델 없음) | 자동 박스 제안 |

## 2. 실행 환경과 그 한계

| 항목 | 값 |
|---|---|
| 브라우저 | Chromium 1194 (headless), 4코어 |
| GPU | **없음** — WebGL은 SwiftShader(소프트웨어), WebGPU는 어댑터 없음 |
| 런타임 | `@mediapipe/tasks-vision@1.0.1` (npm, Apache-2.0), SIMD WASM 빌드 |
| 모델 | MediaPipe 공개 스토리지의 버전 고정 경로 |
| 서빙 | 로컬 정적 서버. **COOP/COEP 있음·없음 두 벌** — GitHub Pages는 헤더를 못 붙인다 |

한계 셋을 먼저 적는다. 판정을 읽을 때 이 셋이 같이 읽혀야 한다.

1. **GPU가 없다.** GPU 델리게이트 수치는 소프트웨어 래스터라이저의 것이고,
   실기기 예측치가 아니다 — 블러·캔버스 사이클과 같은 구도다.
2. **소재가 합성이다.** 정확도를 IoU로 재려면 정답 마스크가 정확히 알려져야 하고,
   그래서 아트를 내려받는 대신 그렸다. 실제 게임 원화의 질감은 없다(§6).
3. **transformers.js·SAM 계열을 재지 못했다.** 이 컨테이너의 이그레스 정책이
   `huggingface.co`·`cdn.jsdelivr.net`을 막는다(403). 후보에서 탈락한 것이
   아니라 **측정하지 못한 것**이다.

### 2.1 픽스처 — 게임 아트가 어려운 세 가지 방식

`artifacts/kv-ai-p0/fixtures.js`가 1080×1920으로 그린다. 정답 마스크는 오브젝트
레이어의 알파 그대로라 오차가 0이다.

| 픽스처 | 무엇이 어려운가 | 정답 면적 | 클릭 |
|---|---|---|---|
| `bonfire` | 광원 — 경계가 없다. bloom이 배경으로 연속적으로 사라진다 | 1.0% | (0.50, 0.68) |
| `character` | 윤곽은 뚜렷하지만 배경 기둥과 명도가 겹치고, 림라이트가 걸려 있다 | 5.9% | (0.50, 0.45) |
| `orb` | 같은 색조의 장식(마법진·입자) 안에 박힌 작은 광원 | 1.3% | (0.50, 0.42) |

## 3. 판정 — `node artifacts/kv-ai-p0/verify.mjs`

### 3.1 클릭 → 마스크

| 픽스처 | 후보 | IoU | 첫 호출 | warm | 마스크 해상도 |
|---|---|---|---|---|---|
| bonfire | **v1 CPU** | **0.979** | 821ms | **573ms** | 1080×1920 |
| bonfire | v1 GPU(SwiftShader) | 0.983 | 6223ms | 2438ms | 1080×1920 |
| bonfire | v2 CPU | 0.984 | 10960ms | 9701ms | 1080×1920 |
| bonfire | v2 GPU(SwiftShader) | 0.010 | 53734ms | 52866ms | — 파손 |
| bonfire | 플러드 필 (tol 90) | 0.901 | 6ms | 6ms | — |
| character | **v1 CPU** | **0.837** | 576ms | **553ms** | 1080×1920 |
| character | v1 GPU(SwiftShader) | 0.886 | 2364ms | 2127ms | 1080×1920 |
| character | v2 CPU | 0.854 | 9866ms | 9351ms | 1080×1920 |
| character | 플러드 필 (tol 24) | **0.170** | 146ms | 146ms | — |
| orb | **v1 CPU** | **0.984** | 582ms | **646ms** | 1080×1920 |
| orb | v2 CPU | 0.986 | 9327ms | 9368ms | 1080×1920 |
| orb | 플러드 필 (tol 90) | 0.468 | 1ms | 1ms | — |

읽기:

- **v1 CPU가 답이다.** 세 픽스처 모두에서 실용 정확도, 0.55~0.65초, 마스크는
  입력과 같은 1080×1920 — 업샘플링이 필요 없다. 반환 박스는 정답 박스와
  소수점 셋째 자리까지 겹친다(bonfire 0.428/0.621/0.144×0.102 vs 정답
  0.429/0.620/0.143×0.101).
- **v2(29.1MB)는 크기값을 못 한다.** 정확도 이득이 +0.005·+0.017·+0.002인데
  CPU에서 **17배 느리다**(9.4초). 인코더/디코더 분리(`setImage`/`segment`)가
  재클릭을 싸게 만들 것으로 봤으나, CPU 경로에서 두 번째 클릭은 9.06초로 첫
  클릭과 같았다 — 분리의 이득이 관찰되지 않았다.
- **플러드 필은 캐릭터에서 무너진다.** 허용오차 24에서 이미 화면의 28%를 삼키고
  IoU 0.17, 허용오차를 올릴수록 나빠진다(0.078 → 0.062, 커버리지 91%). 반대로
  어두운 배경 위 광원(bonfire 0.90)에는 꽤 통한다. **모델 없는 클릭 지정은
  광원 전용**이라는 것이 이 줄의 결론이고, 요청자가 원한 캐릭터는 여기 없다.
- **GPU 델리게이트는 이 환경에서 판정 불가.** v1은 4배 느려지고 v2는 마스크
  자체가 깨진다(IoU 0.01). SwiftShader에서 나온 수치라 실기기 예측치로 쓰면
  안 된다 — 실기기 재측정 항목이다.

### 3.2 COOP/COEP — GitHub Pages 제약은 문제가 아니다

같은 측정을 격리 헤더 있음/없음으로 두 벌 돌렸다.

| | crossOriginIsolated | SharedArrayBuffer | v1 CPU warm (bonfire/character/orb) |
|---|---|---|---|
| pages (헤더 없음) | false | false | 573 / 553 / 646ms |
| isolated (헤더 있음) | true | true | 554 / 583 / 542ms |

차이는 측정 잡음 범위다. **정적 Pages가 헤더를 못 붙이는 것이 이 기능의
제약이 아니다** — 스레드 없는 SIMD WASM 경로로 충분하다.

### 3.3 자동 후보 제안

| 픽스처 | 후보 | 박스 IoU | 시간 | 무엇을 찾았나 |
|---|---|---|---|---|
| bonfire | EfficientDet-Lite0 | 0 | 282ms | 0.2 이상 아무것도 없음 |
| bonfire | **밝은 영역** | **0.849** | 7ms | 1개, luma ≥ 0.688 |
| character | EfficientDet-Lite0 | 0.093 | 204ms | `cup` 0.228 |
| character | 밝은 영역 | 0.003 | 6ms | 1개(림라이트 조각) |
| orb | EfficientDet-Lite0 | 0.916 | 190ms | `mouse` 0.235 |
| orb | **밝은 영역** | **0.929** | 1ms | 1개, luma ≥ 0.700 |

읽기:

- **COCO 디텍터는 게임 아트에서 쓸 수 없다.** 불꽃에는 아무 반응이 없고,
  캐릭터는 `cup` 0.228, 광구는 `mouse` 0.235다. 광구의 **박스는 맞았지만
  라벨이 틀렸다** — 승인 UI에 "마우스"라고 띄울 수는 없다. 13.2MB를 이것에
  쓸 이유가 없다.
- **밝은 영역은 0MB·1~7ms로 광원을 짚는다.** 그리고 캐릭터는 제안하지 않는다.
  이 앱의 이펙트(불티·글로우)가 걸리는 대상이 곧 **빛나는 것**이므로, 이건
  실패가 아니라 정확한 의미론이다. 자동 후보는 모델이 아니라 밝기로 하는 편이
  낫다.

### 3.4 마스크 저장 — 프로젝트 파일 1MB 상한과의 관계

`MAX_PROJECT_FILE_BYTES = 1_000_000` (`domain/editor/projectFile.ts`)이 이미
있는 상한이다. v1 CPU 마스크를 세 해상도로 인코딩했다.

| 픽스처 | 해상도 | IoU | 전해상도 대비 | 런 수 | RLE | RLE base64 | PNG dataURL |
|---|---|---|---|---|---|---|---|
| bonfire | 1080×1920 | 0.979 | 1.000 | 397 | 0.7KB | **0.9KB** | 49.3KB |
| bonfire | 270×480 | 0.966 | 0.977 | 101 | 0.2KB | 0.2KB | 4.9KB |
| character | 1080×1920 | 0.837 | 1.000 | 1461 | 2.6KB | **3.5KB** | 50.0KB |
| character | 270×480 | 0.833 | 0.983 | 365 | 0.5KB | 0.8KB | 5.0KB |
| orb | 1080×1920 | 0.984 | 1.000 | 369 | 0.7KB | **0.9KB** | 49.3KB |
| orb | 135×240 | 0.957 | 0.957 | 49 | 0.1KB | 0.1KB | 1.8KB |

읽기: **전해상도 RLE가 이미 싸다.** 최악(캐릭터) 3.5KB × 상한치인 슬롯 8개 ×
오브젝트 8개 = 224KB로 1MB 안이다. PNG dataURL은 같은 마스크에 49KB를 쓰고
(같은 정보에 14배), 축소는 KB를 더 줄이지만 얻는 게 없다. 마스크 하나는 대개
큰 덩어리 몇 개라 런 길이가 길고, 그게 RLE가 이기는 이유다.

### 3.5 임계값 — 재추론 없는 조절 노브

`node artifacts/kv-ai-p0/probe-mask.mjs`. v1은 두 출력을 함께 낸다: 이진
카테고리 마스크와, 값이 [0,1]인 **확신도 필드**. §3.1의 IoU는 카테고리
마스크 기준이고(클릭 지점의 라벨을 오브젝트로 잡는다), 아래는 확신도 필드를
임계값별로 다시 이진화한 것이다 — 같은 한 번의 추론에서 나온 두 읽기다.

| 픽스처 | 중간값 픽셀 비율 | IoU @0.2 | @0.35 | @0.5 | @0.65 | @0.8 |
|---|---|---|---|---|---|---|
| bonfire | 0.10% | 0.958 | 0.973 | 0.981 | **0.986** | 0.982 |
| character | 1.14% | **0.918** | 0.861 | 0.837 | 0.819 | 0.807 |
| orb | 0.10% | 0.971 | 0.978 | **0.984** | 0.982 | 0.979 |

**캐릭터가 임계값 하나로 0.837 → 0.918로 올라간다.** 필드는 이미 손에 있으므로
재이진화에 추론이 필요 없다 — "느슨하게 / 타이트하게" 슬라이더가 공짜다. 기본값을
0.5로 두면 안 된다는 것도 같이 나온다: 윤곽이 뚜렷한 대상일수록 낮은 임계값이 낫다.

## 4. 함의

1. **클릭 → 마스크는 이 앱에서 성립한다.** 서버 없이, 소재를 내보내지 않고,
   17.2MB·0.6초로. 모델이 이미지를 받는 것이지 이미지가 어디로 가는 게 아니다.
2. **작은 쪽이 이긴다.** v2는 5배 무겁고 17배 느린데 정확도가 사실상 같다.
   크기·속도 예산은 v1으로 잡는다.
3. **모델 없는 경로는 광원 전용이다.** 플러드 필(캐릭터 0.17)과 COCO
   디텍터(`cup` 0.228)가 각각 클릭 지정과 자동 제안에서 탈락한다. 대신 밝은
   영역 검출이 **자동 제안**의 자리를 0MB로 채운다 — 이 앱의 이펙트가 겨냥하는
   것이 정확히 광원이기 때문이다.
4. **마스크는 프로젝트 파일에 들어간다.** 전해상도 RLE 0.9~3.5KB. 즉 마스크를
   값으로 굳혀 저장할 수 있고, 그래야 **렌더가 모델에 의존하지 않는다** —
   kv-object-animation FR-O04(결정론)가 요구하는 구조가 그대로 유지된다.
5. **정적 Pages 제약은 통과다.** COOP/COEP 없이 같은 속도가 난다.
6. **임계값은 UI로 노출할 값이다.** 재추론 0으로 캐릭터 IoU +0.08.

## 5. 미해결 — 실기기·실소재로 넘어가는 것

| 항목 | 왜 여기서 못 하나 | 어디서 판정하나 |
|---|---|---|
| 실제 게임 키비주얼에서의 정확도 | 컨테이너에 실소재가 없다. 합성 픽스처는 정답이 정확할 뿐 질감이 없다 | M0 — 요청자 키비주얼로, IoU가 아니라 **수정 없이 승인되는 비율**로 |
| GPU/WebGPU 델리게이트 | GPU가 없다 (SwiftShader) | 실기기 |
| 첫 사용 네트워크 시간 | 로컬 서버에서만 쟀다 | 실기기 |
| transformers.js·SAM 계열 | 이그레스 정책이 HF·jsDelivr 차단(403) | **재지 않는다** — 요청자가 v1으로 확정(Plan D-A02). M0에서 v1이 미달일 때만 다시 꺼낸다 |
| `magic_touch` 모델 라이선스 | `ai.google.dev` 차단 | Plan 확정 전 확인 — **사용이 아니라 재배포 권리로**: 요청자가 모델을 배포본에 담기로 정했으므로(Plan D-A03) 우리 도메인이 이 파일을 서빙한다. 런타임은 Apache-2.0 확인됨 |
| `InteractiveSegmenterLegacy` 폐기 위험 | v1은 `Legacy` 클래스로만 접근된다 | 버전 고정 + Design에서 어댑터 격리 |

## 6. 이 문서를 어디까지 믿을 것인가

정확도 숫자는 **그린 그림**에서 나왔다. 형태가 단순하고 경계가 깨끗하므로
실제 원화보다 쉬웠을 가능성이 크고, 반대로 게임 아트 특유의 림라이트·bloom·
비사실적 색은 사진으로 학습한 모델에 불리하다 — 어느 쪽으로 틀렸는지는 실소재
전에는 알 수 없다. **배송 무게·속도·저장 크기·헤더 제약·후보 간 순위**는
소재에 거의 무관하므로 그대로 쓸 수 있고, **절대 정확도**는 M0에서 다시 잰다.

## 7. 재현

```bash
node artifacts/kv-ai-p0/prepare.mjs        # 런타임·모델 내려받기 (out/, gitignored)
KV_AI_P0_CHROME=/opt/pw-browsers/chromium-1194/chrome-linux/chrome \
  node artifacts/kv-ai-p0/run.mjs          # 두 벌(헤더 없음/있음) 측정 → out/results.json
node artifacts/kv-ai-p0/verify.mjs         # 표 출력
KV_AI_P0_CHROME=… node artifacts/kv-ai-p0/probe-mask.mjs   # §3.5 임계값 스윕
```

전체 측정은 약 11분(대부분 v2 CPU). `KV_AI_P0_CHROME`을 시스템 Chrome으로
바꾸면 실기기 GPU 경로가 같은 스크립트로 재측정된다.
