딸려가지 않는다 — 의도대로.

## 3. NFR-R02 — 컨테이너의 블러 비용 경고는 실기기에서 소멸했다

진단 로그의 타이밍: `waitForReady=169ms, createFrame=991ms, addSample=5505ms,
audioMixing=32ms` — 총 ≈6.7초.

- 래스터화 버킷(`createFrame`)이 **900프레임에 991ms ≈ 1.1ms/프레임**, 블러
  40프레임 포함. 컨테이너 소프트웨어 경로의 1.25초/프레임(m0-blur-spike §2.1)
  대비 **~1000배** — 우려했던 +50초 시나리오는 존재하지 않는다.
- 블러 초과분의 상한 추정: 비블러 프레임이 ~1.0ms라면 초과분은 40프레임에
  ~130ms, 총 렌더의 **≈2%**. 게이트(5%) 통과로 판정한다. §2.1의 완화책
  (램프 계단화 등)은 불필요.
- 렌더가 encode 지배(`addSample` 82%)라는 것도 확인 — 블러·왕복은 병목이 아니다.
