## 1. 무엇을 만들었나

Day1의 2단계 대비를 4단계로 늘린 템플릿. 영상 4개를 2×2 그리드에 배치하고, 한 번에
하나만 재생하며 나머지 셋은 자기 트림-인 프레임에 흑백으로 정지한다.

| 항목 | 값 |
|---|---|
| 템플릿 키 | `day1-quad` · UI 표기 `Day1(4 video)` · 파일명 세그먼트 `day1x4` |
| 시간축 | `[panel-a, panel-b, panel-c, panel-d, endcard]` 5구간 |
| 길이 | 15 · 30초 (60초 미제공, 전환 시 30초로 강제 변환) |
| 라벨 | 패널 4개 × 4언어, 기본값 `Day1`/`Day2`/`Day3`/`Day7` |
| 엔드카드 | Day1과 완전히 동일 (스키마·컴포지션 공유, 신규 코드 0줄) |

### 2.2 검증되지 않은 것 — 반드시 남는 항목

**실제 MP4 렌더가 이 환경에서 한 번도 실행되지 않았다.** 원격 컨테이너의 Chromium에
H.264 인코더도 디코더도 없고, 네트워크 정책이 실제 Chrome 설치를 막는다
([M0 §1](../03-analysis/day1-quad.m0-perf-gate.md)).

따라서 다음은 **미검증**이다:

| 미검증 항목 | 덮는 곳 |
|---|---|
| SC1 3규격 MP4 산출 | `tests/e2e/day1-quad.spec.ts` |
| SC3 흑백이 **MP4에** 남는지 (프리뷰로는 확인됨) | 같은 스펙 |
| SC4 십자 분할선의 렌더 픽셀 색 | 같은 스펙 |
| 파일명 단정 8곳 | 기존 E2E |
| 선택기 조작 12곳 | 기존 E2E |

## 4. 실측이 바꾼 판단 두 가지

**① 축퇴 설계가 불필요해졌다.** 계획은 1.5배 초과 시 "정지 패널을 PNG로 사전 추출"을
예비안으로 뒀는데, 패널 개수 비용이 1.15배로 작아 그 복잡도를 도입할 이유가 없어졌다.

**② 프록시가 4분할에서는 덜 필요하다.** 2×2 셀이 출력 종횡비를 그대로 가지므로,
출력과 같은 방향의 소스는 `cover`에서 이미 거의 완벽히 맞는다. `planPanelProxy`가
`MIN_PROXY_SAVINGS`(20%) 아래로 판단해 트랜스코드를 건너뛴다 — 2분할에서는 세로 소스가
높이의 절반을 잃어 프록시가 항상 필요했던 것과 대조된다. 방향이 어긋난 소스(9:16에
가로 영상)에서는 여전히 68% 절약으로 프록시가 동작한다.

## 5. 브라우저 검증이 아니면 못 잡았을 결함

`useMediaSession.retain`은 목록에 없는 오브젝트 URL을 해제하는데, 워크스페이스가 그
목록에 `panelA`/`panelB`만 넣고 있었다. 4분할에서 **세 번째 패널을 올리는 순간 앞의
두 개가 해제되어 네 패널이 전부 "연결 필요"로 떨어졌다.**

유닛 테스트로는 잡히지 않는 종류다 — 도메인은 전부 옳았고, 증상은 세션 URL 수명에만
나타난다. Day1은 2패널이라 아무 증상이 없어서, **두 템플릿을 나란히 돌려 비교하고서야**
드러났다. 이 사이클에서 브라우저 검증이 값을 한 지점이다.
