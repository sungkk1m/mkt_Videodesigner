# failure-video Plan — 실패(FAIL) 영상 템플릿

> **Summary**: 레퍼런스 광고 포맷(레벨 1 실패 → 레벨 20 → 레벨 99 성장 서사)을 재현하는 다섯 번째 템플릿 `failure`.
> **Project**: mkt_videodesigner
> **Feature key**: `failure-video`
> **Date**: 2026-08-28 · **Status**: Plan (레퍼런스 실측·사용자 결정 완료, Design 대기) — 코드 변경 없음.
> 입력: 사용자 제공 레퍼런스 mp4(360×640 @30fps, 50.0s) 프레임 단위 실측 + 아키텍처 조사.

## Executive Summary

| 관점 | 내용 |
|---|---|
| Problem | "실패 → 성장" 서사형 UA 소재(레벨 1에서 FAIL 도장 → 레벨 20 → 레벨 99)를 만들 템플릿이 없다. 기존 4개 템플릿은 분할 비교(day1/quad)·루핑(kv-loop)·3장면(three-scene) 구조라 순차 서사 + 오버레이 효과를 담지 못한다. |
| Solution | 새 템플릿 kind `failure`: 구간당 영상 1종 × 3구간(레퍼런스 준수) + FAIL 스탬프 효과(구간 1 마지막 고정) + 줌 펀치 전환 + 하단 레벨 캡션 바 + day1과 동일한 엔드카드. 세로(9:16)·가로(16:9) 전용. |
| Function UX Effect | UA 매니저가 게임 녹화 3~4개 업로드만으로 레퍼런스와 동일한 포맷의 소재를 로케일×2비율 배치 렌더로 뽑는다. |
| Core Value | 검증된 광고 포맷을 소재 교체만으로 반복 생산 — day1 계열과 동일한 "업로드 → 트림 → 렌더" 워크플로 유지. |

## 1. 레퍼런스 실측 (원본: 사용자 업로드 mp4)

### 1.1 전체 구조 (1fps 전수 + 구간별 10~30fps 실측)

| 구간 | 시간 | 내용 | 하단 캡션 |
|---|---|---|---|
| 세그먼트 1 | 0.0–9.6s (19%) | Level 1 게임플레이 — 사망 → **FAIL 효과** → 게임 자체 패배 화면 → 로비 | `LEVEL 1` |
| 전환 1 | 9.4–10.0s | 줌 펀치 전환 (§1.3) | 캡션 포함 줌 |
| 세그먼트 2 | 10.0–14.4s (9%) | Level 20 게임플레이 (장비 강화 UI) | `LEVEL 20` |
| 전환 2 | 14.4–15.0s | 동일 전환 | 캡션 포함 줌 |
| 세그먼트 3 | 15.0–50.0s (72%) | Level 99 게임플레이 (보스전·만렙 장비) | `LEVEL 99` |
| 엔드카드 | **없음** | 레퍼런스는 게임플레이로 끝남 — 엔드카드는 본 템플릿의 추가 요구 | — |

### 1.2 FAIL 효과 (30fps 프레임 단위, 2.9–4.5s)

1. **죽음 펀치 줌** — ~3.0s부터 화면 중심(죽는 캐릭터)으로 부드러운 줌인 ≈0.6s, 스케일 ≈1→2.2, ease-out.
   3.0s에 임팩트 SFX 스파이크(RMS −9.7dB, 전 구간 평균 −17.5dB 대비 +8dB).
2. **탈색** — 줌 도중 게임 화면이 그레이스케일로 전환(소스 게임 자체 연출로 추정 — 템플릿에서는 토글로 재현).
3. **스탬프 슬램** — 3.70s에 빨간 그런지(고무도장) 질감 `FAIL`이 화면보다 크게(≈4×) 반투명+모션블러로 등장
   → ~4.1s에 스케일 다운하며 안착. 안착 상태: 약 −8° 회전, 프레임 좌우로 삐져나가는 폭, 화면 높이 15–55% 구간,
   드롭섀도, 불투명도 0.6→1.0.
4. **스크린 셰이크** — 안착 직후 캡션 바 포함 프레임 전체가 수 프레임 ±10px급 흔들림.
5. **소멸** — 4.5s 컷. 이후 "You lost the battle!"은 소스 푸티지 내용(게임 화면)이며 템플릿 효과가 아니다.

효과 전체 ≈1.5s(줌 시작~스탬프 소멸), 스탬프 노출 자체 ≈0.8–1.0s.

### 1.3 줌 펀치 전환 (10fps, 두 전환 동일)

- 아웃고잉: 화면 중심으로 급격 줌인 ~0.2s, 모션블러 동반. **캡션 바 포함 프레임 전체**가 줌된다.
- 컷 후 인커밍: 줌인 상태(≈2×)에서 ~0.3s에 걸쳐 스케일 1.0으로 안착(ease-out). 수직 팬 성분 소량.
- 총 ≈0.5–0.7s. 전환 자체의 SFX 스파이크는 없음(게임 오디오 연속).

### 1.4 하단 캡션 바 (full-res 픽셀 실측)

- 순수 블랙 바, 높이 = 프레임 높이의 **10%** (360×640 기준 y 576–640).
- 흰색 볼드 대문자 `LEVEL N`, 중앙 정렬, 폭 ≈ 프레임 폭의 40%, 캡 높이 ≈ 프레임 높이의 3.7%.
- 게임 푸티지는 상단 90% 영역에 폭 기준 채움(하단이 바에 가려지는 크롭).

### 1.5 Remotion 재현 가능성 — **가능, 전부 기존 검증 프리미티브로**

사용자 확인 요청 항목("전환 효과가 Remotion으로 가능한지")에 대한 결론. 필요한 프리미티브가 모두
이 저장소에서 **웹 렌더러로 MP4에 구워지는 것까지 검증**된 상태다:

| 필요 효과 | 기존 검증 사례 |
|---|---|
| 스케일+블러 줌 펀치 | `KvLoopComposition.tsx:75-121` BlurBookend — `filter: blur` + `transform: scale`, 효과 밖 프레임은 `style undefined`로 비용 0 |
| 구간 경계 전환(Σframes 불변 유지) | `domain/render/transition.ts:14-49` `transitionStyleAt()` — 각 섹션 자기 프레임 범위 안에서 동작 |

## 3. 왜 별도 템플릿인가 — 기존 구조에서 막히는 지점

| 요구 | 기존 구조의 한계 |
|---|---|
| 순차 3구간 + 오버레이 효과 | day1/quad는 "동시 분할 + 활성 패널 전환" 구조(`QuadFrame.tsx:61-70`), three-scene은 hook/gameplay/cta 고정 의미(`SCENE_ORDER`, `constants.ts:4`) |
| FAIL 스탬프·줌 펀치·셰이크 | `stamp/shake/punch` 코드 부재(grep 확인). 신규 도메인 함수 + 컴포지션 레이어 필요 |
| 방향별 소스 슬롯 | `day1PanelSchema:268`는 소스 1개 + 비율별 transform(`ratioTransformsSchema:104`)만 — 소스 자체의 방향 축이 없다 |
| 비율 2종 제한 | 전 템플릿 3비율 허용, kv-loop만 단일 고정(`KV_LOOP_RATIO`, `constants.ts:111`). 2종 부분집합 패턴은 신설이지만 동일 3점 세트(refine + switchTemplate 강제 + 선택기 경고)로 성립 |

반면 재사용 기반은 충분하다: 섹션 축 `[2,8]`(`constants.ts:29-30`)이 4섹션(`panel-a/b/c` + `endcard`)을 그대로 수용해
**`PROJECT_SCHEMA_VERSION = 2` 유지·마이그레이션 0건**, 엔드카드는 스키마·커맨드·컴포지션 전부 재사용(quad 때 "신규 코드 0줄" 선례),
타임라인 경계 이동·트림 재조정·미디어 영속화·배치 렌더·프록시 준비는 템플릿 무관 공통 경로다. conventions.md §3.1
"템플릿 추가 = arm 2개" 규칙을 그대로 따른다.

## 4. Requirements

### Functional (Must)

- **FR-01 템플릿 kind `failure`** — `TEMPLATE_KINDS` 추가, 섹션 `['panel-a','panel-b','panel-c','endcard']`
  (id는 quad와 동일한 panel 계열로 유지해 패널 기계장치 재사용, 표시명은 라벨이 담당). 스키마 버전 2 유지.
- **FR-02 구간당 영상 1종 × 3구간** — 각 구간은 단일 소스를 상단 90% 영역에 렌더(분할 없음).
  트림·프레이밍(fit/scale/offset)은 day1 패널 방식 재사용.
- **FR-03 방향별 소스 슬롯** — 각 구간이 세로용·가로용 소스(+트림)를 따로 가진다. 9:16 렌더는 세로 슬롯,
  16:9 렌더는 가로 슬롯을 사용. 선택된 렌더 비율에 해당하는 슬롯이 비면 preflight 에러(자동 폴백 없음 — Q2 결정).
- **FR-04 FAIL 효과, 구간 1 마지막 고정** — 구간 1의 마지막 1.5s 창(줌 리드인 0.5s + 스탬프 1.0s)에 §1.2 효과를 재현:
  중심 펀치 줌(1→2.2) + 탈색 램프 + 내장 스탬프 슬램(4×→1, −8°, 불투명도 0.6→1, 효과 프레임에만 블러) + 결정적 셰이크.
  경계 이동 시 창이 경계를 따라간다(섹션 프레임의 순수 함수). 요소별 토글 제공(탈색·줌은 소스에 이미 있을 수 있음).
- **FR-05 줌 펀치 전환** — 구간 1→2, 2→3 경계에 §1.3 전환(아웃 0.25s 줌인+블러 / 인 0.3s 줌아웃 안착).
  캡션 바를 포함한 프레임 전체에 적용(레퍼런스 동일). `transitionStyleAt()` 패턴으로 Σframes 불변 유지.
- **FR-06 하단 캡션 바** — 높이 10% 블랙 바 + 중앙 흰색 볼드 텍스트. 문구는 `copy.failureLabels`(구간별,
  기본 `LEVEL 1`/`LEVEL 20`/`LEVEL 99`, 로케일별 관리). 엔드카드 구간에는 미표시.
- **FR-07 엔드카드** — day1-quad와 동일: 마지막 섹션 3000ms 기본(`DAY1_END_CARD_MS`), `day1EndCardSchema`·
  `EndCardScene`·트림 커맨드 재사용. 신규 코드 0줄 목표.
- **FR-08 비율 9:16·16:9 전용** — 프리뷰·배치 렌더 모두 2종으로 제한(1:1 차단). kv-loop 고정 패턴의 부분집합판.
- **FR-09 길이 프리셋 30/60초** — `durationPresetsForTemplate` arm. 기본 구간 배분은 레퍼런스 비율:
  엔드카드 3s 선취 후 잔여를 20% / 10% / 70%(마지막 구간이 잔여 전부의 우수리 흡수). 경계는 타임라인에서 조정 가능.
- **FR-10 렌더 경로** — `buildEditorSnapshot`·`createEditorRenderRequest` arm, 프록시 준비(`planPanelProxy`) 경유
  (`architecture.test.ts:160-179` 강제), 파일명 세그먼트(`TEMPLATE_FILE_SEGMENT`) 추가.

### Functional (Should)

- **FR-11 스탬프 SFX** — 슬램 시점 임팩트 사운드 1발(레퍼런스 +8dB 스파이크 재현). `generate-poc-audio.mjs` 방식의
  합성 에셋 또는 CC0 샘플, 토글 가능. 미확보 시 Do 단계에서 무음 출고 허용.
- **FR-12 줌 초점 조정** — 펀치 줌 중심점 오프셋(기본 중앙). 죽는 캐릭터가 화면 중앙이 아닐 때 대비.

### Non-Functional

- **NFR-01 렌더 비용** — 블러·필터는 효과 프레임에만(`BlurBookend` 규칙: 효과 밖 `style undefined`).
  quad 실측(상시 blur 배경 2.13× 렌더 시간, `day1-quad.plan.md:377-383`)의 재발 방지.
- **NFR-02 결정성** — 셰이크 포함 모든 효과는 `(frame, fps, …)` 순수 도메인 함수. 스크럽·프리뷰·렌더·배치 일치.
- **NFR-03 규약 준수** — domain은 React/Remotion 무의존, 컴포지션은 스토어 무의존, 커맨드는 타 템플릿에서 no-op,
  Zod `.default()`로 저장 문서 무마이그레이션.

## 6. Success Criteria

- **SC1 스키마·도메인 유닛 그린** — arm 파싱, 섹션 id 순서, 30/60 외 프리셋 거부, 9:16/16:9 외 비율 거부,
  저장 문서 라운드트립(`.default()` 누락 검증), `switchTemplate` 강제 변환, 구간 배분 함수(합=프리셋, 각 ≥ `MIN_SCENE_MS`,
  구간 1 ≥ FAIL 창), 경계 이동 시 FAIL 창 추종.
- **SC2 FAIL 효과 실측** — 렌더된 MP4에서 구간 1 마지막 1초 프레임의 스탬프 적색 픽셀 + 탈색(채도 강하)을
  `videoSampling.ts`(`sampleRegion`/`meanSaturation`)로 단언.
- **SC3 전환 실측** — 경계 ±0.2s 프레임에서 캡션 바 상단 에지의 휴지 위치 이탈(줌 증거)과 경계 밖 프레임의 정위치 복귀를 단언.
- **SC4 캡션 바 실측** — 세 구간 각각에서 하단 10% 블랙 + 흰 텍스트 존재, 구간별 문구 상이함을 단언.
- **SC5 엔드카드** — 마지막 3s에 엔드카드 영상 재생(quad e2e 검증 방식 재사용).
- **SC6 스위트 그린** — `npm test`(아키텍처 경계 포함) + `npm run build`(tsc -b 3설정) + `tests/e2e/failure.spec.ts`
  (스위치 → 업로드 → 문구 → 프리뷰 → 실 MP4 1건, 30초 프리셋).
- **SC7 렌더 비용** — failure 렌더 시간이 동일 소스 day1 단일 패널 대비 +15% 이내(효과 프레임 비중이 낮으므로;
  실측으로 확정, `run-render-benchmark.mjs` 활용).

## 8. Decision Log

- **D-1 섹션 id를 quad와 같은 `panel-*` 계열로** — 패널 키 기반 기계장치(`panelKeysOf`, 프록시, 에셋 패널) 재사용 극대화.
  표시명은 캡션 라벨이 담당하므로 id 의미 충돌 없음.
- **D-2 방향별 소스는 "한 프로젝트 안의 슬롯 2벌"로** (대안: 세로/가로 프로젝트 2개 분리) — 한 배치에서
  로케일×(9:16, 16:9)를 함께 뽑는 기존 배치 설계(`render.selectedRatios`)와 문구·엔드카드 단일 관리를 지키기 위함.
  프로젝트 2개 분리안은 문구 수정이 이중화되어 기각. 정확한 스키마 형상(day1PanelSchema 2벌 vs 신설 failurePanelSchema)은
  Design에서 확정.
- **D-3 FAIL 창은 "구간 1 끝 앵커" 상수** — 사용자 요구 "마지막 1초 고정"을 스탬프 노출 1.0s + 리드인 0.5s로 해석.
  레퍼런스 실측(§1.2)과 일치.
- **D-4 기본 구간 배분 20/10/70** — 레퍼런스 실측 비율(19/9/72)의 라운딩. 경계는 어차피 타임라인에서 조정 가능하므로
  기본값 논쟁을 줄이고 실측을 따른다.
- **D-5 효과는 전부 토글** — 탈색·펀치 줌은 소스 게임이 자체 연출로 이미 갖고 있을 수 있어(레퍼런스가 그 사례)
  중복 적용을 피할 스위치가 필요하다.

## 10. Plan 단계에서 코드를 건드리지 않은 이유

Design 문서 작성의 입력이다.
