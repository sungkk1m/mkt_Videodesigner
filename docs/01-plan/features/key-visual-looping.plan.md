## Executive Summary

| Perspective | Content |
|-------------|---------|
| **Problem** | 기존 두 템플릿은 모두 **영상 소재**를 전제하고, 시간축이 `[구간, 구간, 구간]` 3튜플로 고정되어 있다. 실제 UA 라인업에서 반복 생산되는 포맷 중 하나인 "키비주얼 루핑"(정지 일러스트 4장을 순환시켜 세로형 인트로 영상을 만드는 것)은 소재가 이미지이고 구간 수가 KV 장수만큼 필요해서 지금 구조로는 만들 수 없다. 레퍼런스 6본(까부리 4언어, 모닥불 2언어)이 모두 외부 편집 도구에서 수작업으로 나왔고, 언어를 하나 추가할 때마다 전체를 다시 만든다. |
| **Solution** | `templateSettings`에 `kv-loop` arm을 추가하고, 3튜플이던 `sections`를 가변 길이 배열로 넓혀 **KV 1장 = 구간 1개**로 매핑한다. 반복은 `loopCount`로 분리해 타임라인에는 한 사이클만 보이게 한다. KV 이미지 셋은 언어별로 두고 미설정 언어는 `en` 셋을 상속하므로, 언어 추가는 이미지 교체만으로 끝난다. 출력은 9:16 전용이다. |
| **Function/UX Effect** | 사용자는 헤더에서 "키비주얼 루핑"을 고르고, KV 이미지를 순서대로 2~8장 올린 뒤 타임라인 경계를 끌어 장당 홀드 시간을 불균등하게 맞추고(레퍼런스처럼 1.9/2.4/2.3/3.1초), 반복 횟수를 고르고, 필요하면 상단 타이틀 PNG와 하단 고지문구를 얹는다. 언어 탭을 바꿔 그 언어의 KV만 교체하면 4언어 배치 렌더가 한 번에 나간다. |
| **Core Value** | 지금까지 외부 도구에서 언어별로 통째로 재작업했던 포맷을 브라우저 안에서 "이미지 교체 → 배치 렌더"로 줄인다. 부수적으로 시간축이 가변 길이가 되면서, 앞으로 구간 수가 3이 아닌 UA 포맷(랭킹 나열, 아이템 쇼케이스 등)을 스키마 재설계 없이 얹을 수 있는 기반이 생긴다. |

## 1. Overview

### 1.1 Purpose

정지 키비주얼 여러 장을 순환 재생하는 세로형 루핑 영상을 편집기 안에서 만든다. 부수적으로, 시간축을 3구간 고정에서 가변 길이로 넓혀 이후 템플릿이 구간 수에 묶이지 않게 한다.

### 1.2 Background

레퍼런스는 `C:\Users\superplanet-market\Desktop\mkt_looping reference\` 의 MP4 6본이다. `ffprobe`와 씬 컷 검출로 실측한 결과는 다음과 같다.

| | 까부리 인트로루핑 (2024-01-08) | 모닥불 / Under Dark 루핑 (2025-01-17) |
|---|---|---|
| 규격·코덱 | 1080×1920 · 30fps · H.264 + AAC | 동일 |
| 총 길이 | 19.0s (570 프레임) | 16.0s (480 프레임) |
| KV 장수 | 4장 — 모닥불 · 제단 · 온천 · 산등성이 | 4장 — 회색 · 초록 · 붉은 · 얼음 모닥불 |
| KV별 홀드 | 1.87 / 2.40 / 2.30 / 3.07s (**불균등**) | 2.0s 균등 |
| 사이클 | 9.63s × **2회** | 8.0s × **2회** |
| 전환 | 컷 3회 + 블러 디졸브 1회 | 전 구간 크로스페이드 |
| 고정 오버레이 | 상단 "조선 퇴마사 / 까부리" 타이틀 | 상단 "Under Dark" 로고 + 하단 "확률형 아이템 포함" |
| 언어 본수 | 4본 (KR / EN / JP / CT) | 2본 (KR / ENG) |
| 오디오 | BGM만 (원본 사운드 개념 없음) | 동일 |

현재 코드의 제약은 하나로 모인다. `sections`가 3튜플로 고정되어 있고([schema.ts:214](../../../src/domain/editor/schema.ts:214)), 총 길이 불변식이 `sum(sections) === durationPreset × 1000`이며, `moveBoundary()`·`allocateSceneFrames()`가 3-튜플을 하드코딩한다([timeline.ts](../../../src/domain/timeline/timeline.ts)). KV 4장 + 2회 반복은 이 전제를 모두 벗어난다.

다행히 확장 비용은 작다. 3구간 가정에 실제로 의존하는 코드는 `timeline.ts`의 `sectionDurationsOf`/`moveBoundary`/`allocateSceneFrames`와 [EditorWorkspace.tsx:1092](../../../src/features/editor/EditorWorkspace.tsx:1092)의 Day1 경계 읽기 두 곳뿐이고, `SECTION_COUNT`는 선언만 되어 있고 참조가 없다. 나머지는 이미 템플릿 무관하게 작성되어 있다.

이미지 경로도 이미 열려 있다. `mediaKindSchema`에 `image`가 있고([reference.ts:8](../../../src/domain/media/reference.ts:8)), Dropzone이 `image/*`를 받고, `EndCardScene`이 `<Img>` + ken-burns 모션을 이미 구현해 두었다([EndCardScene.tsx:53](../../../src/compositions/day1/EndCardScene.tsx:53)). 새로 만들 것은 컴포지션과 인스펙터이고, 재료는 대부분 있다.

`conventions.md` §3.1이 "템플릿 추가는 스키마 변경이 아니라 arm 2개 추가 — `templateSettings`에 하나, `buildEditorSnapshot()`에 하나"라고 규정한다. 이번 작업은 그 규약을 따르되, 시간축 가변화라는 공통 축 변경을 **한 번** 동반한다.

### 1.3 Confirmed Product Decisions

착수 전 사용자 확인을 거친 항목이다. Design 단계에서 뒤집지 않는다.

| # | 결정 | 근거 |
|---|------|------|
| L1 | **구간 = KV 1장, 반복은 `loopCount`로 분리** | 타임라인에 한 사이클(4클립)만 보여야 경계 드래그로 레퍼런스의 불균등 홀드(1.87/2.40/2.30/3.07s)를 그대로 맞출 수 있다. 반복까지 펼치면 같은 KV를 8곳에서 따로 만져야 한다 |
| L2 | **총 길이는 기존 프리셋 15 / 30 / 60초 유지** | 15초 · 4장 · 2회 = 장당 1.875초로 모닥불(2.0초)과 사실상 구분되지 않는다. 프리셋을 건드리면 `SCENE_DURATION_PRESETS_MS`·프리셋 버튼·파일명 규칙까지 영향이 번지는데 그만한 이득이 없다. 레퍼런스의 정확한 16초·19초는 재현하지 않는다 |
| L3 | **9:16 전용 템플릿** | 레퍼런스 6본 전부 세로형이고, 세로 KV를 1:1·16:9로 내보내면 크게 잘린다. 규격별 재프레이밍을 붙이면 KV 4장 × 3규격 = 최대 12곳을 수작업으로 맞춰야 한다. 1:1·16:9가 실제로 필요해지면 별도 사이클로 다룬다 |
| L4 | **KV 이미지 셋은 언어별, 미설정 언어는 `en` 셋을 상속** | 까부리는 타이틀이 KV에 박힌 4본 구조다. 언어별 셋이 있어야 이 케이스를 정면으로 지원한다. 폴백을 `ko`가 아니라 `en`으로 둔 것은, 제작하지 않은 언어(예: JP)가 영어본으로 나가는 것이 UA 관행에 맞기 때문이다. 따라서 **`en` 셋을 먼저 채우는 것을 권장**한다 |
| L5 | **상단 타이틀·로고 오버레이는 선택 사항. 없어도 렌더·다운로드가 된다** | 타이틀이 KV에 이미 박혀 있는 경우가 대부분이다. Day1이 "패널 영상 2개 없으면 렌더 차단"으로 간 것과 **반대 방향**이며, 렌더 프리플라이트 게이트는 KV 이미지만 필수로 잡는다 |
| L6 | **하단 고지문구를 4언어 텍스트로 지원** | 모닥불 레퍼런스의 "확률형 아이템 포함"이 이 자리다. bannerdesigner의 disclaimer 정책(nowrap + 글자수 힌트)을 그대로 들여온다 |
| L7 | **KV별 Ken Burns + KV 사이 크로스페이드** | 정지 이미지 특유의 밋밋함을 없애는 최소 장치이고, 모닥불 레퍼런스의 인상에 가장 가깝다. `EndCardScene`의 ken-burns 구현과 `TRANSITION_KINDS`의 `fade`를 재사용한다 |
| L8 | **KV 2~8장 / 반복 1~4회. 장당 1초 미만 조합은 차단** | 레퍼런스(4장·2회)를 여유롭게 포함한다. 기존 `MIN_SCENE_MS`(1초) 하한 때문에 `프리셋초 ÷ 반복횟수 < KV장수` 인 조합(예: 15초·8장·2회 = 937ms)은 성립하지 않으므로, 조용히 보정하지 않고 이유를 밝힌 메시지로 차단한다 |
| L9 | **사운드는 업로드 BGM만. 나레이션·TTS 탭은 숨긴다** | 이미지 소재라 원본 사운드가 없다. 기존 `audioTrackSchema`의 BGM(업로드·루프·볼륨·시작지점)이 그대로 요구를 충족한다. 나레이션 스키마는 `sceneKind`(hook/gameplay/cta) 키에 묶여 있어, 루핑에서 쓰려면 키 일반화가 추가로 필요한데 레퍼런스에 그 수요가 없다. Day1이 Hook·카피 탭을 숨긴 선례(D14)를 따른다 |

## 2. Scope

### 2.1 In Scope

**시간축 가변화 (공통 축 변경)**

- `sections`를 3튜플에서 최소 2 · 최대 8 항목의 배열로 넓힌다. 기존 v2 문서는 3항목 배열이므로 **그대로 파싱된다 — `schemaVersion` 승격도, 마이그레이션 코드도 없다**.
- `moveBoundary()`·`allocateSceneFrames()`·`sectionDurationsOf()`를 임의 길이로 일반화한다. 총 길이 불변식, 구간 최소 1초, 마지막 구간이 반올림 잔여를 흡수하는 규칙은 모두 유지한다.
- 기존 두 템플릿은 항목 수 3으로 고정되어 동작이 바뀌지 않는다.

**`kv-loop` 템플릿**

| 축 | 내용 |
|----|------|
| 소재 | 언어별 KV 이미지 셋 2~8장 (순서 있음). 미설정 언어는 `en` 셋 상속 |
| 구간 | KV 1장 = 구간 1개. 경계 드래그로 장당 홀드 시간 조절, 총 길이 불변 |
| 반복 | `loopCount` 1~4회. 사이클을 그대로 이어 붙인다 |
| 모션 | KV별 Ken Burns (`ken-burns` / `none`), 강도 조절 |
| 전환 | KV 사이 크로스페이드. 지속시간 조절 (기존 100~1000ms 범위) |
| 오버레이 | 상단 타이틀·로고 PNG (언어별, **선택**) + 하단 고지문구 (4언어 텍스트, 선택) |
| 오디오 | 업로드 BGM (루프·볼륨·시작지점) |
| 출력 | 9:16 고정 · 30/60fps · 4언어 배치 |
| 마감 | 마지막 사이클 끝에서 블랙 페이드아웃 (레퍼런스 재현, Should) |

**기존 경로 재사용**

렌더 프로필(Fast/Standard/High), Batch 큐·취소·재시도, IndexedDB 자동저장·복구, JSON 내보내기·가져오기, 파일명 규칙, 소재 재연결(relink)을 그대로 쓴다.

### 2.2 Out of Scope

- **1:1 · 16:9 출력** — L3. 루핑 템플릿을 고르면 규격 선택지가 9:16으로 고정된다.
- **규격별 KV 셋 분리 업로드** — L3에서 배제.
- **나레이션 · TTS · 더킹** — L9. UI를 숨기며, 스키마의 나레이션 필드는 건드리지 않는다.
- **KV별 자막** — 오버레이는 전 구간 고정 타이틀과 고정 고지문구 두 종류뿐이다.
- **텍스트로 입력하는 타이틀** — 게임 로고 특유의 커스텀 서체를 웹폰트로 재현할 수 없어 PNG 업로드로 간다.
- **블러 디졸브 전환** — 까부리에 1회 등장하지만, 크로스페이드로 대체한다. 필요해지면 `TRANSITION_KINDS`에 arm 추가로 후속 처리.
- **CTA · 엔드카드** — 레퍼런스는 순수 인트로 루핑이고 CTA가 없다.
- **레퍼런스와 총 길이 정확 일치 (16초 · 19초)** — L2.
- **Hook 분석 · 후보 추천** — 이미지 소재에 적용 개념이 없다.

### 2.3 Prerequisite

없다. 다른 저장소 선행 작업 없이 이 저장소 안에서 완결된다. (Day1의 bannerdesigner 16:9 의존과 다른 점이다.)

| ID | 요구사항 |
|----|----------|
| NFR-L01 | 15초 · 9:16 · Standard 루핑 렌더 시간이 동일 조건 3장면 기준선 **이하**여야 한다. 이미지 디코딩이 비디오보다 싸므로 초과하면 구현에 문제가 있다는 신호로 본다 |

## 4. Success Criteria

### 4.1 Definition of Done

| # | 기준 | 검증 방법 |
|---|------|-----------|
| SC1 | KV 4장 · 2회 반복으로 9:16 MP4가 실제로 나온다 | E2E + `ffprobe`로 1080×1920 · 지정 fps · H.264 · 총 길이 확인 |
| SC2 | 장당 홀드 타이밍이 지정값대로 렌더된다 | 씬 컷 검출로 전환 시점을 뽑아 지정 경계와 **±1 프레임** 이내 일치 |
| SC3 | 반복 사이클이 실제로 동일하다 | 사이클 1과 사이클 2의 대응 프레임을 추출해 픽셀 차이가 인코딩 오차 범위 내인지 확인 |
| SC4 | 크로스페이드가 렌더 결과물에 반영된다 | 전환 구간 중간 프레임이 양쪽 KV의 혼합인지 확인 (단일 KV와의 차분이 양쪽 모두 0이 아님) |
| SC5 | **타이틀·고지문구를 하나도 올리지 않은 상태에서 렌더·다운로드가 완료된다** | E2E: KV만 올린 프로젝트로 렌더 → 파일 생성 확인. FR-L13 검증 |
| SC6 | 미설정 언어가 `en` 셋으로 렌더된다 | `en`·`ko` 셋만 채운 프로젝트로 4언어 배치 → `ja`·`zh-TW` 산출물이 `en` KV와 동일한지 프레임 비교 |
| SC7 | 유효하지 않은 장수·반복 조합이 이유와 함께 차단된다 | 유닛: 15초·8장·2회가 차단되고 메시지에 대안이 포함되는지 |
| SC8 | 기존 3장면 · Day1 프로젝트가 회귀 없이 열리고 렌더된다 | 기존 유닛 415 + E2E 54 전량 통과 + v1/v2 JSON 가져오기 테스트 |
| SC9 | 유닛 · E2E 전부 통과, 타입체크 · 빌드 통과 | `npm test && npm run build && npm run test:e2e` |

### 4.2 Quality Criteria

- 루핑 도메인 로직(사이클 프레임 배분, `en` 폴백 해석, 유효 조합 판정, 가변 길이 경계 이동)은 순수 함수로 분리하고 유닛 테스트를 붙인다.
- 시간축 가변화는 **기존 두 템플릿의 회귀 테스트를 먼저 통과시킨 뒤** 루핑 arm을 얹는다. 순서를 뒤집지 않는다.
- `sections` 배열 확장이 기존 3항목 문서를 그대로 파싱하는지 왕복 테스트한다 (v1 · v2 픽스처 양쪽).
- 레퍼런스 대조는 스크린샷 비교가 아니라 §4.1의 프레임 추출 측정으로 한다.

### 4.3 Performance Gate

Design 착수 전 **이미지 루핑 렌더 스파이크**를 돌린다. 기존 `npm run benchmark:render` 하네스를 재사용해 "1080×1920 PNG 4장 · Ken Burns · 크로스페이드 · 2회 반복" 구성의 15초 9:16 렌더 시간을 실측하고 3장면 기준선과 비교한다.

기준선을 넘으면 원인을 먼저 특정한다 — Ken Burns의 `transform: scale()`이 매 프레임 리샘플을 유발하는지, 크로스페이드 구간에서 이미지 2장이 동시에 합성되는 비용인지. Ken Burns가 원인이면 강도 상한을 낮추고, 합성이 원인이면 전환 구간만 사전 렌더하는 설계를 택한다.

## 5. Risks and Mitigation

| 위험 | 영향 | 대응 |
|------|------|------|
| `sections` 3튜플 확장이 기존 두 템플릿을 회귀시킨다 | **높음** | 이번 작업의 최대 위험이다. 가변화를 단독 모듈로 먼저 끝내고, 그 모듈 종료 시점에 기존 유닛·E2E 전량을 통과시킨 뒤에만 루핑 arm으로 넘어간다. 기존 두 템플릿은 항목 수 3으로 고정해 입력 공간을 넓히지 않는다 |
| 사이클을 프레임으로 나눌 때 나누어떨어지지 않는다 | 중간 | 15초 · 30fps · 4회 = 사이클 112.5 프레임처럼 실제로 발생한다. 반복까지 펼친 전체 구간 목록에 프레임을 배분하고 **마지막 구간이 잔여를 흡수**하는, `allocateSceneFrames`의 기존 규칙을 그대로 적용한다. SC3(사이클 동일성)은 이 1프레임 오차를 허용 범위에 포함한다 |
| 고해상도 PNG를 언어×장수만큼 들고 있어 메모리가 터진다 | 중간 | FR-L18 다운스케일 캐시. §4.3 스파이크에서 KV 8장 × 4언어를 올린 상태의 메모리를 함께 실측한다 |
| 9:16 고정이 `renderSettings`에 "템플릿별 허용 규격" 개념을 새로 들인다 | 중간 | 스키마의 `selectedRatios`를 넓히지 않고, 루핑 arm의 `superRefine`에서 `['9:16']`만 허용하는 방식으로 좁힌다. 템플릿 전환 시 규격 선택을 강제 보정하고 그 사실을 전환 다이얼로그에 명시한다 |
| `en` 폴백이 의도와 다르게 동작해 엉뚱한 언어 산출물이 나간다 | 중간 | 어느 셋을 상속 중인지 자산 패널에 항상 표시한다(FR-L04). `en` 셋이 비어 있으면 그 언어 job만 프리플라이트에서 막고, 나머지 언어는 계속 렌더한다 (기존 Batch의 job별 실패·재시도 경로 활용) |
| 정지 이미지 루핑이 밋밋해 레퍼런스 느낌이 안 난다 | 중간 | Ken Burns + 크로스페이드가 최소 장치다(L7). §4.3 스파이크 산출물을 레퍼런스와 나란히 두고 Design 착수 전에 눈으로 확인한다 |
| 루핑이 기존 코드를 오염시킨다 | 중간 | Day1과 동일한 방어선 — 판별자로 컴포지션·인스펙터를 분리하고, 매 모듈 종료마다 기존 E2E 전량 실행 |

**마이그레이션 없음.** `sections`를 튜플에서 배열로 넓히는 것은 기존 3항목 문서에 대해 하위 호환이고, `kv-loop`은 판별 유니온에 arm을 더하는 것이라 기존 문서를 건드리지 않는다. `PROJECT_SCHEMA_VERSION`은 2를 유지한다 — day1-endcard-video가 `.default()`로 마이그레이션 코드 없이 스키마를 늘린 것과 같은 방식이다.

### 6.2 Current Consumers

기존 3장면 · Day1 경로 전체가 소비자다. **`template` 판별자로 분기해 기존 경로의 동작은 바꾸지 않는다**는 것이 Day1 때와 동일한 회귀 방어선이다. 다만 이번에는 `sections` 가변화라는 **공통 축 변경**이 있어, 판별자 분기만으로는 방어되지 않는 부분이 있다. §5의 첫 번째 위험이 이것이고, 대응은 "가변화를 단독 모듈로 먼저 끝내고 기존 테스트 전량 통과 후 진행"이다.

### 6.3 Verification

각 모듈 종료 시 `npm test && npm run build`, 모듈 묶음 종료 시 `npm run test:e2e` 전량. 시간축 가변화 모듈은 **기존 테스트만으로** 종료 판정한다 (새 기능이 없으므로 회귀 없음이 곧 완료다).
