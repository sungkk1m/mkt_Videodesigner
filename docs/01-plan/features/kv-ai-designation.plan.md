## 1. Overview

### 1.1 무엇을 만드는가

지정에 층이 하나 더 생긴다. 기존 두 경로는 그대로 남고, 그 앞에 AI가 선다.

| 층 | 동작 | 실패하면 |
|---|---|---|
| **자동 후보** | KV를 열면 이펙트를 걸 만한 곳(광원)을 앱이 먼저 짚어 목록으로 보여준다. 사용자는 승인(→ 이펙트 오브젝트 생성)·거절 | 목록이 비어 있을 뿐, 클릭 지정이 남는다 |
| **클릭 → 마스크** | 미리보기에서 오브젝트를 클릭하면 온디바이스 모델이 윤곽 마스크를 제안한다. 사용자는 여유값 조절·추가/제외 클릭·승인·거절 | 사각형 드래그 지정이 그대로 남는다 |
| **직접 지정** | kv-object-animation이 배송한 드래그 사각형·점 | — |

세 층 전부에서 **확정하는 것은 사용자**다. AI가 만드는 것은 후보이지 상태가 아니다.

### 1.2 경계 원칙 — AI는 편집 시점의 도구다

이 사이클이 지켜야 하는 선은 하나로 요약된다: **모델은 스키마를 만드는 도구이고,
렌더의 입력이 아니다.**

지정이 확정되는 순간 마스크는 픽셀 값의 배열로 스키마에 굳는다. 그 뒤로:

- 렌더는 모델 없이 돈다 — kv-object-animation FR-O04(같은 프로젝트는 언제,
  몇 번째 렌더든 같은 프레임)가 그대로 성립한다. 모델 버전이 바뀌어도 이미
  만든 영상은 바뀌지 않는다.
- 배치 렌더(언어 × 비율 최대 12개)가 모델을 12번 돌리지 않는다.
- JSON으로 내보낸 프로젝트가 다른 기기에서 모델 없이 열린다.
- 모델 로드가 실패해도 **프로젝트는 무손상**이고, 직접 지정 경로가 남는다.

§1.4.5의 실측이 이 원칙을 가능하게 한다: 전해상도 마스크 하나가 RLE로
0.9~3.5KB라, 프로젝트 파일 1MB 상한 안에 넉넉히 들어간다.

### 1.3 마스크가 렌더에 닿는 방식

세 가지가 새로 필요하다. 전부 Design에서 확정하되, Plan 단계에서 **성립
가능성**만 확인해 둔다.

| 문제 | 해법의 방향 | 왜 성립하나 |
|---|---|---|
| **좌표계** — 마스크는 이미지에서 나오고 이펙트는 프레임 좌표에서 그려진다 | 마스크를 **이미지 정규 좌표**로 저장하고, 그릴 때 `objectFit`(cover/contain) 매핑을 통과시킨다 | `MediaReference`가 이미 `width`·`height`를 갖는다 — 매핑이 프로젝트 값만으로 계산된다. 사용자 프레이밍(`slot.x/y/scale`)과 카메라는 캔버스가 이미 같은 transform으로 받는다(kv-object-animation D-04) |
| **파티클 방출점** — 지금은 rect 안 균등 난수. 마스크 안에서 뽑아야 한다 | 마스크에서 파생한 **내부 셀 목록**(마스크의 순수 함수, 메모이즈)을 만들고 `hash01(seed, i, k) × N`으로 색인 | 기각 샘플링과 달리 반복 횟수가 없어 닫힌 식이 유지된다 — D-03(결정론)이 깨지지 않는다 |
| **글로우의 모양** — 지금은 radial gradient | 마스크를 알파로 쓰고 흐림을 먹여 halo를 만든다 | 캔버스 2D의 `filter`로 가능. **다만 비용은 미지수** — 북엔드 블러의 전례(소프트웨어 경로 프레임당 1.25초)가 있으므로 M2에서 실측한다 |

SC1(지정 밖 무변화)의 판정 근거인 "도달 범위의 닫힌 식"도 유지된다 — rect가
마스크의 bounding box로 바뀔 뿐, `kvParticlesReach`의 형태는 같다.

### 1.4 기술 후보 실측 — P0 스파이크

kv-object-animation Plan §1.4가 "조사 항목"으로 남긴 표를, 이번에는 숫자로
채운다. 전체 수치·방법·한계는
[p0-designation-spike](../../03-analysis/kv-ai-designation.p0-designation-spike.md).

네 후보를 같은 소재·같은 클릭으로 비교했다. 소재는 정답 마스크가 정확히
알려지도록 **그렸다** — 게임 아트가 어려운 세 방식(경계 없는 광원, 배경과
명도가 겹치는 캐릭터, 장식에 박힌 작은 광원)을 각각 겨냥한 1080×1920 픽스처 3장.

#### 1.4.1 클릭 → 마스크

| 후보 | IoU (불꽃/캐릭터/광구) | warm 응답 | 첫 사용 무게 |
|---|---|---|---|
| **MediaPipe Interactive Segmenter v1** (magic_touch) | **0.979 / 0.837 / 0.984** | **0.55~0.65초** | **17.2MB** |
| MediaPipe Interactive Segmenter v2 | 0.984 / 0.854 / 0.986 | 9.4초 | 40.3MB |
| 플러드 필 (모델 없음) | 0.901 / **0.170** / 0.468 | 1~146ms | 0MB |
| transformers.js·SAM 계열 | — | — | — |

- **v1이 답이다.** 마스크가 입력과 같은 1080×1920으로 나오고, 반환 박스가 정답
  박스와 소수점 셋째 자리까지 겹친다.
- **v2는 크기값을 못 한다** — 5배 무겁고 CPU에서 17배 느린데 정확도 이득이
  +0.005~+0.017이다. 인코더/디코더 분리로 재클릭이 싸질 것으로 봤으나, 두 번째
  클릭도 9.06초로 같았다.
- **모델 없는 클릭 지정은 광원 전용이다.** 캐릭터에서 플러드 필은 허용오차
  24에서 이미 화면의 28%를 삼키고 IoU 0.17이다. 요청자가 원한 대상이 정확히
  여기서 빠진다.
- **transformers.js·SAM 계열은 측정하지 못했다** — 이 컨테이너의 이그레스 정책이
  `huggingface.co`를 막는다(403). 탈락이 아니라 미실측이다(§1.4.6).

#### 1.4.2 자동 후보 제안

| 후보 | 박스 IoU (불꽃/캐릭터/광구) | 시간 | 무게 |
|---|---|---|---|
| EfficientDet-Lite0 (COCO) | 0 / 0.093 / 0.916 | 190~282ms | 13.2MB |
| **밝은 영역 연결성분** (모델 없음) | **0.849 / 0.003 / 0.929** | **1~7ms** | **0MB** |

COCO 디텍터는 게임 아트에서 쓸 수 없다 — 불꽃에는 반응이 없고, 캐릭터는
`cup` 0.228, 광구는 `mouse` 0.235다. 박스는 맞아도 라벨이 틀려서 승인 UI에
띄울 수 없다.

밝은 영역은 0MB·수 ms로 광원을 짚고, 캐릭터는 제안하지 않는다. **이 앱의
이펙트(불티·글로우)가 걸리는 대상이 곧 빛나는 것**이므로 이건 실패가 아니라
정확한 의미론이다 — 자동 제안은 모델이 아니라 밝기로 하는 편이 낫다.

#### 1.4.3 정적 Pages 제약 — 통과

같은 측정을 COOP/COEP 헤더 있음/없음 두 벌로 돌렸다. v1 warm 응답이
573/553/646ms(헤더 없음) vs 554/583/542ms(있음) — 측정 잡음 범위다.
헤더를 못 붙이는 정적 Pages가 이 기능의 제약이 아니다.

#### 1.4.4 임계값 — 재추론 없는 조절 노브

v1은 이진 마스크와 함께 [0,1] 확신도 필드를 낸다. 필드를 다시 이진화하는 데는
추론이 필요 없다.

| 픽스처 | IoU @0.2 | @0.5 | @0.65 |
|---|---|---|---|
| 불꽃 | 0.958 | 0.981 | **0.986** |
| 캐릭터 | **0.918** | 0.837 | 0.819 |
| 광구 | 0.971 | **0.984** | 0.982 |

**캐릭터가 임계값 하나로 0.837 → 0.918로 오른다.** "느슨하게 / 타이트하게"
슬라이더가 공짜로 생기고, 기본값을 0.5로 두면 안 된다는 것도 같이 나온다.

#### 1.4.5 마스크 저장 — 1MB 상한과의 관계

| 형식 | 마스크 하나 (불꽃/캐릭터/광구) |
|---|---|
| **전해상도 RLE, base64** | **0.9 / 3.5 / 0.9 KB** |
| 전해상도 PNG dataURL | 49.3 / 50.0 / 49.3 KB |
| 1/4 축소 RLE, base64 | 0.2 / 0.8 / 0.2 KB (IoU 손실 ≤0.004) |

최악값 3.5KB × 상한치인 슬롯 8개 × 오브젝트 8개 = 224KB로 1MB 안이다.
**축소할 이유가 없다** — 전해상도를 그대로 담아도 예산이 남는다.

#### 1.4.6 이 표를 어디까지 믿을 것인가

정확도 숫자는 **그린 그림**에서 나왔다. 형태가 단순해 실제 원화보다 쉬웠을
수도 있고, 게임 아트 특유의 림라이트·bloom·비사실적 색이 사진으로 학습한
모델에 불리할 수도 있다 — 어느 쪽인지는 실소재 전에 알 수 없다.

| 소재에 거의 무관 → 그대로 쓴다 | 소재에 좌우됨 → M0에서 다시 잰다 |
|---|---|
| 배송 무게, 응답 시간, 저장 크기, 헤더 제약, **후보 간 순위** | **절대 정확도**, 승인 없이 쓸 수 있는 비율 |

컨테이너에 GPU가 없어(SwiftShader) GPU 델리게이트 수치도 실기기 예측치가 아니다.
블러·캔버스 사이클과 같은 구도이고, 같은 방식으로 실기기에서 다시 잰다.

### 1.5 Decisions Needed Before Design

설계 착수 전 확인이 필요한 항목이다. "기본 제안"은 §1.4의 실측에서 나온 것이고,
근거 칸이 그 출처다.

| # | 질문 | 기본 제안 | 근거 |
|---|---|---|---|
| **D-A01** | 1차 범위 — 클릭→마스크만인가, 자동 후보 제안까지인가 | **둘 다.** 단 자동 후보는 모델이 아니라 밝은 영역 검출로 — 0MB·수 ms이고, 이 앱의 이펙트가 겨냥하는 대상과 의미가 정확히 겹친다 | §1.4.2 |
| **D-A02** | 클릭→마스크의 기술 | **MediaPipe Interactive Segmenter v1(magic_touch) + Tasks Vision WASM.** v2는 크기·속도값을 못 하고, 모델 없는 경로는 캐릭터에서 무너진다 | §1.4.1 |
| **D-A03** | 런타임·모델의 배송 | **WASM은 npm 의존성으로 빌드에 포함**(락파일이 버전을 고정, 외부 호스트 없음), **모델은 핀된 MediaPipe 경로에서 사용자가 AI 지정을 처음 누를 때만** 내려받는다 — TTS 모델의 전례(`shared/config/models.ts`)와 같은 규약 | §1.4.1, README 네트워크 정책 |
| **D-A04** | 마스크의 저장 형식 | **전해상도 이진 마스크의 RLE(base64 문자열).** 축소도 PNG도 이점이 없다 | §1.4.5 |
| **D-A05** | 마스크는 스키마의 어느 축에 붙는가 | **지정의 형태**로 붙인다 — `region`을 `{shape: 'rect' \| 'mask'}` 유니온으로 열고, 이펙트 종류(`particles`/`glow`)는 그대로 둔다. kv-object-animation Design이 "마스크는 새 `kind`"로 예상한 부분을 뒤집는 제안이다: 마스크는 "무엇을"이 아니라 "어디에"이고, `kind`에 넣으면 (종류 × 형태)로 조합이 폭발한다 | Design §2.1 재검토 |
| **D-A06** | 마스크의 좌표계 | **이미지 정규 좌표(0-1) + 그릴 때 `objectFit` 매핑.** 프레임 좌표로 굳히면 사용자가 나중에 `fit`이나 프레이밍을 바꿨을 때 마스크가 원화에서 떨어진다 | §1.3 |
| **D-A07** | 사용자 수정의 범위 | **① 여유값 슬라이더(재이진화, 추론 0) ② 추가/제외 클릭(재추론) ③ 거절 → 사각형 지정.** 픽셀 브러시 직접 페인팅은 범위 밖 | §1.4.4 |
| **D-A08** | 오브젝트 모션(지정한 오브젝트 자체의 줌) 포함 여부 | **다음 사이클.** 다만 관찰 하나를 다음 Plan의 입력으로 남긴다: **확대(배율 ≥ 1)만 허용하면 구멍이 생기지 않는다** — 커진 컷아웃이 자기 구멍을 덮으므로 인페인팅이 필요 없다. 축소는 배경이 드러나 채움 전략이 선행돼야 한다 | [report §5](../../04-report/kv-object-animation.report.md) |
| **D-A09** | 외부 vision API 옵트인 경로 | **범위 밖.** 온디바이스가 실측으로 성립하므로, 만들지 않은 경로에는 유출 위험도 없다. 필요가 실증되면 별도 사이클 | §1.4.1, CLAUDE.md §2 |
| **D-A10** | 게이트 — 무엇을 얼마로 판정하나 | **정확도는 IoU가 아니라 "수정 없이 승인되는 비율"로**, 요청자의 실제 키비주얼로 판정한다. 성능은 클릭→마스크 응답을 실기기에서 잰다. 두 기준값은 M0에서 요청자와 함께 확정한다 — 숫자를 발명하지 않는다 | §1.4.6, D-05 전례 |

## 4. Success Criteria

### 4.1 Definition of Done

| SC | 판정 방법 |
|---|---|
| SC-A1 | 요청자의 실제 키비주얼에서 클릭→마스크가 **수정 없이 승인되는 비율**이 M0에서 정한 기준 이상 (D-A10) |
| SC-A2 | 마스크 지정 이펙트가 마스크 도달 범위 밖 픽셀을 바꾸지 않는다 — on/off 렌더 비교, 코덱 노이즈 이하 (SC1의 마스크판) |
| SC-A3 | 같은 프로젝트를 두 번 렌더하면 프레임 단위로 동일하고, **모델을 로드하지 않은 세션에서도** 같다 (FR-A07) |
| SC-A4 | 마스크가 카메라·프레이밍·`fit` 변경을 따라간다 — 원화 위 같은 자리 (FR-A09) |
| SC-A5 | 클릭→마스크 응답 시간이 실기기에서 정한 게이트 이내 (D-A10) |
| SC-A6 | 마스크 이펙트 켠 렌더 시간이 게이트 이내 (NFR-A03) |
| SC-A7 | 상한치 구성(슬롯 8 × 오브젝트 8)의 프로젝트가 1MB 안에서 내보내지고 다시 읽힌다 (NFR-A01) |
| SC-A8 | 모델 로드를 강제로 실패시켜도 편집·렌더·저장이 전부 동작한다 (FR-A11) |
| SC-A9 | AI 지정을 누르기 전에는 모델 관련 네트워크 요청이 0건이고, 소재는 어떤 요청에도 실리지 않는다 (FR-A10/A12) |
| SC-A10 | 기존 단위 테스트와 E2E가 회귀 없이 통과한다 |

### 4.2 이 환경에서 판정 가능한 것과 아닌 것

| 판정 | 여기서 | 이유 |
|---|---|---|
| SC-A2·SC-A3·SC-A4·SC-A7 | ✅ (VP9) | 수치·구조 판정은 코덱 독립 — 이전 두 사이클과 같은 논리 |
| SC-A8·SC-A9·SC-A10 | ✅ | 단위 + 네트워크 관찰 E2E, 코덱 불필요 |
| SC-A1 | ❌ | 실소재가 없다. **요청자 키비주얼이 있어야 시작된다** |
| SC-A5·SC-A6 | 부분 | 컨테이너는 GPU가 없어 상한 추정. 실기기가 진짜 판정 |

**M0의 실소재 정확도 게이트가 이 사이클의 착수 게이트이고, M5의 실기기 렌더
판정이 종료 게이트다.** 앞의 것이 새로 생긴 이유는, 이 사이클에서 처음으로
"품질"이 코드가 아니라 모델에 달려 있기 때문이다.

## 5. Risks and Mitigation

| 위험 | 영향 | 완화 |
|---|---|---|
| 실제 게임 원화에서 정확도가 픽스처만 못하다 | 클릭 지정이 "매번 고쳐야 하는 기능"이 된다 | M0을 **착수 게이트**로 둔다. 미달이면 순서대로: ① 여유값 기본값 재조정(§1.4.4에서 +0.08의 여지 확인) ② 추가/제외 클릭으로 보정 가능한지 ③ 마스크를 광원 자동 후보에만 쓰고 캐릭터는 사각형 유지 ④ 미실측 후보(SAM 계열) 재검토 |
| 첫 사용 17.2MB가 체감상 길다 | 기능을 한 번 써보고 안 쓴다 | 모델은 명시적 요청 시에만(D-A03) — 안 쓰는 사용자는 1바이트도 받지 않는다. 진행률과 취소를 붙이고, 실기기 시간을 M0에서 잰다 |
| 마스크 글로우의 흐림이 비싸다 | 렌더 시간 폭증 (블러 전례: 소프트웨어 경로 프레임당 1.25초) | M2에서 on/off 실측을 먼저 하고, 비싸면 흐림을 **지정 시점에 한 번 구워** 마스크와 함께 저장하는 쪽으로 선회한다 — 프레임마다 같은 모양이므로 프레임 함수일 필요가 없다 |
| 마스크는 슬롯(언어 공통)에 저장되는데 이미지는 언어별이다 | 언어마다 원화가 다르면 마스크가 어긋난다 | 마스크를 이미지 정규 좌표로 두면 종횡비가 달라도 매핑은 성립한다(D-A06). 내용 자체가 다른 경우는 UI에서 드러나게 한다 — Design에서 확정할 항목 |
| `InteractiveSegmenterLegacy`가 폐기된다 | 업그레이드가 막힌다 | 버전을 락파일로 고정하고, 접근을 `ObjectDesignator` 어댑터 한 파일로 격리한다(NFR-A05). v2로의 이전은 어댑터 한 곳의 교체가 된다 |
| 모델 라이선스가 상업적 사용을 제한한다 | 배포 불가 | Design 확정 전에 확인한다(§2.3). Remotion과 같은 취급 — 조건과 경계를 문서로 남긴다 |
| 마스크가 스키마를 부풀린다 | 프로젝트 파일 상한 초과 | 실측상 여유가 크다(224KB / 1MB, §1.4.5). 상한치 구성 테스트를 SC-A7로 고정 |
| AI 경로가 직접 지정을 회귀시킨다 | 되던 것이 안 된다 | 마스크는 지정 **형태**의 추가이지 대체가 아니다(D-A05). 기존 rect 경로의 단위·E2E를 그대로 유지 |

### 6.2 Current Consumers

- `kvEffectSchema`를 읽는 곳은 `KvEffectsCanvas`(드로잉)와 `KvEffectOverlay`(편집)
  둘이고, 만드는 곳은 `project.ts`의 세 커맨드다. 지정 형태를 유니온으로 열면
  **이 다섯 곳만** 형태를 분기한다 — `buildKvLoopProps`는 지금처럼 통과만 시킨다.
- `kvParticlesAt`은 `effect.region`에서 출생점을 뽑는다. 여기가 형태 분기가
  도메인에 닿는 유일한 지점이고, `kvParticlesReach`가 그 짝이다.
- `KvSlotRenderProps`에는 지금 이미지 치수가 없다 — 마스크 매핑에 필요하므로
  `buildKvLoopProps`가 해당 로케일 `MediaReference`의 `width`·`height`를 실어야
  한다. 이펙트를 "해석 없이 통과"시키던 규약이 여기서 한 칸 넓어진다.
- `src/test/architecture.test.ts`가 계층 의존을 검사한다 — 새 `infrastructure/vision/`
  경로와 모델 런타임 임포트는 그 규칙표에 등록돼야 한다.

### 6.3 Verification

단위 테스트는 순수 함수에 집중한다 — RLE 왕복 동일성, 마스크 bbox의 닫힌 식,
내부 셀 목록이 같은 (시드, 프레임)에 같은 방출점을 주는지, 이미지→프레임 매핑이
`cover`·`contain`과 종횡비 조합에서 맞는지, 밝은 영역 검출이 알려진 입력에서
알려진 박스를 내는지. 포트는 가짜 어댑터로 실패·취소 경로까지 테스트한다.
E2E는 지정 세션의 UI 상태와 **네트워크 관찰**(SC-A9)을 맡고, 마스크 픽셀 판정은
M2 하네스와 실기기 게이트가 맡는다 — 캔버스 내용은 DOM 문자열로 읽히지 않는다.

답이 나오지 않는다.
