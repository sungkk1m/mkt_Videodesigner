## Executive Summary

| 관점 | 내용 |
|---|---|
| **Problem** | Day1 템플릿은 `panelA`/`panelB` 두 패널로 스키마가 고정돼 있어 "Before → After" 2단계만 보여준다. 성장·변화를 **DAY 1 → 7 → 14 → 30** 처럼 4단계로 끌고 가는 소재를 만들 수 없고, 2분할 영상 두 개를 외부 편집기에서 이어 붙여야 한다. |
| **Solution** | `template` 판별자에 `day1-quad` arm을 추가한다. 영상 4개를 2×2 그리드에 배치하고, 시간축은 `[패널 A, B, C, D, 엔드카드]` 5구간이 된다. 분할선·라벨·엔드카드·프록시·Batch는 Day1의 것을 **재사용**한다. |
| **Function/UX Effect** | 헤더 템플릿 선택기에 4번째 항목이 생기고, 애셋 패널이 영상 슬롯 4개, 인스펙터가 패널 4개 + 라벨 4개(×4언어)를 노출한다. 타임라인 경계는 4개가 되고 드래그 조작감은 동일하다. |
| **Core Value** | 이미 검증된 Day1 파이프라인(분할 기하 · 정지 프레임 흑백 · 엔드카드 자동 배치 · crop 프록시 · 4언어×3규격 Batch)을 그대로 쓰면서 서사 단계를 2 → 4로 늘린다. 새로 만드는 것은 **기하와 구간 수뿐**이다. |

## 1. Overview

### 1.1 현재 구조에서 무엇이 걸리는가

읽어서 확인한 사실만 적는다.

| 항목 | 현재 | 4분할에 쓸 수 있는가 |
|---|---|---|
| `sections` 축 | 가변 길이 `[2, 8]` (`constants.ts:MIN/MAX_SECTION_COUNT`) | **그대로 가능.** 5구간은 범위 안 |
| `expectedSectionIds(settings, count)` | 템플릿별 분기, 함수 형태 | **arm 하나 추가로 끝** |
| 타임라인(`timeline.ts`) | `SceneDurationsMs = readonly number[]`, 경계 드래그 N구간 일반화 완료 | **무변경** |
| `templateSettings` | `template`으로 discriminated union | **arm 하나 추가** |
| `day1PanelSchema` / `endCard` 스키마 | `day1SettingsSchema` 안에 인라인 | 공용 상수로 **추출 후 두 arm이 참조** |
| `splitLayout(ratio, lineWidthPx)` | 2분할 전용, `{a, b, line}` 반환 | 4분할용 `quadLayout()` **신규** |
| `activePanelForSection(0|1|2)` | `'a'|'b'|null` | 인덱스 → `'a'..'d'|null` **신규** |
| `SplitFrame.tsx`의 `Panel` | 내부 컴포넌트(비공개) | **파일로 추출해 두 컴포지션이 공유** |
| `EndCardScene.tsx` | 템플릿 무관 | **그대로 재사용** |
| Day1 명령 15종 | `Day1PanelKey = 'panelA'|'panelB'` 키 기반 | 키 유니언을 `panelC`/`panelD`까지 넓히면 **명령 코드 재사용** |
| `panelProxies.ts` | `PANELS` 리스트가 2개 하드코딩 | 리스트를 템플릿에서 받도록 **일반화** |
| `copy.day1Labels` | `{a, b}` (optional 필드) | `c`/`d`를 optional로 추가 → **마이그레이션 없음** |
| `MAX_BATCH_JOBS` / 파일명 / 자동저장 / JSON | 템플릿 무관 | **무변경** |

핵심: **`sections` 가변화(key-visual-looping 사이클)가 이미 끝나 있어서, 4분할은 스키마 버전을 올릴 필요가 없다.** `PROJECT_SCHEMA_VERSION`은 2에 머문다.

### 1.2 왜 별도 템플릿인가

`day1-template` Plan §2.2가 "영상 3개 이상, 가변 분할 개수"를 Out of Scope로 두면서
**"필요해지면 별도 템플릿으로"** 라고 적어 뒀다. 그 결정을 따른다. 근거를 다시 적으면:

- Day1은 PDCA 사이클이 **완료**된(Match Rate 100%) 템플릿이다. `panelA`/`panelB`를
  배열로 바꾸면 저장된 문서의 마이그레이션과 함께 완료된 사이클 전체가 다시 검증 대상이 된다.
- 반면 arm을 하나 더 두면 회귀 표면이 "공용으로 추출한 부분"으로만 좁혀지고,
  그 추출은 **동작이 아니라 위치만 바뀌는 순수 이동**이다.
- conventions §3.1이 명시한 규약과도 일치한다 — *"Adding a template means two arms,
  not a schema change."*

#### Q4의 파급 — `contain` 기본이 무엇을 뜻하는가

`contain`은 남는 자리를 소스 프레임 1장의 블러 사본으로 채운다(`SplitFrame.tsx`의
`BACKDROP_BLUR_RATIO`). 4패널 전부가 `contain`이면 **한 프레임의 video 요소가 최대 8개**
(패널 4 + 블러 배경 4)가 된다. 디코드는 여전히 "재생 1 + 정지 7(1프레임씩)"이라
Q2 결정 덕에 늘지 않지만, **합성 비용(`createFrame`, 렌더 시간의 25.2%)이 이번 사이클의
1번 리스크**가 된다. 그래서:

- **M0 성능 게이트는 `contain` 4패널, 즉 최악 구성으로 측정한다.** `cover` 구성으로
  측정하면 실사용보다 낙관적인 숫자가 나온다.
- 규격별로 셀 종횡비가 출력과 같으므로 **세로 원본을 9:16에 올리면 `contain`에서도
  블러가 사실상 보이지 않는다**(여백 0.25%). 즉 `contain` 기본의 비용은 "규격과 방향이
  어긋난 조합"에서만 실제로 발생한다.
- 패널별 Fit 토글은 Day1 인스펙터에 이미 있으므로 4패널로 확장만 하면 된다(§2.7).

## 2. 설계안

### 2.1 레이아웃 — 2×2 그리드

**왜 2×2인가.** 4분할 방식은 세 가지가 있는데, 셀의 종횡비가 결정적이다.

| 배치 | 9:16 셀 | 1:1 셀 | 16:9 셀 | 판정 |
|---|---|---|---|---|
| **2×2 그리드** | 537×957 (0.561) | 537×537 (1.000) | 957×537 (1.782) | **출력 비율과 사실상 동일** (오차 ≤0.25%) |
| 4행 스트립 | 1080×478 (2.26) | 1080×268 (4.03) | — | 초광각. 세로 캡처가 거의 안 보인다 |
| 1+3 히어로 | 비대칭 | 비대칭 | 비대칭 | 셀마다 프레이밍을 따로 잡아야 한다 |

2×2가 가진 성질 두 개가 그대로 이득이다.

1. **셀 종횡비 = 출력 종횡비.** `1080/2 : 1920/2 = 9:16`. 즉 9:16 출력에서 세로 캡처
   원본은 **crop 없이 셀을 꽉 채운다.** 현재 Day1의 9:16 패널은 1080×957(가로형)이라
   세로 소스의 절반을 버리는데(`day1-render-speed.analysis.md` §3: 디코드 픽셀의 49.8%만
   화면에 닿음), 4분할에서는 그 손실이 사라진다.
2. **규격 간 프레이밍 이식성.** 셀 비율이 규격마다 같으니 9:16에서 잡은 Scale/X/Y가
   1:1·16:9에서도 같은 구도를 준다 → 규격별 override를 덜 만지게 된다.

**기하 (분할선 6px 기준, `quadLayout(ratio, lineWidthPx)`)**

```
        col0   L   col1
      ┌──────┬─┬──────┐
 row0 │  A   │ │  B   │      L = lineWidthPx
      ├──────┼─┼──────┤      십자 분할선 = 세로 1 + 가로 1 = 사각형 2개
 row1 │  C   │ │  D   │
      └──────┴─┴──────┘
```

| 규격 | 출력 | col0 / col1 | row0 / row1 | 셀 종횡비 | 출력 종횡비 | 오차 |
|---|---|---|---|---|---|---|
| 9:16 | 1080×1920 | 537 / 537 | 957 / 957 | 0.5611 | 0.5625 | 0.25% |
| 1:1 | 1080×1080 | 537 / 537 | 537 / 537 | 1.0000 | 1.0000 | 0 |
| 16:9 | 1920×1080 | 957 / 957 | 537 / 537 | 1.7821 | 1.7778 | 0.24% |

`splitLayout`과 같은 규칙을 유지한다 — 나머지 픽셀은 뒤쪽 셀에 주어
`col0 + L + col1 == width`가 정확히 성립하게 한다(1px 이음선 방지).

**재생 순서는 읽기 순서** A(좌상) → B(우상) → C(좌하) → D(우하). 시계방향(A→B→D→C)은
Q3에서 확인.

### 2.2 시간축 — 5구간

```
sections: [panel-a, panel-b, panel-c, panel-d, endcard]
```

`day1QuadSectionDurations(preset)`: 엔드카드가 고정 3초를 먼저 떼고, 남은 시간을 4등분
하며 나머지는 마지막 패널에 준다(Day1의 `day1SectionDurations`와 같은 규칙).

| 프리셋 | 패널당 기본 | 엔드카드 | 검증 |
|---|---|---|---|
| 15초 | 3,000ms | 3,000ms | `MIN_SCENE_MS`(1,000) 통과 |
| 30초 | 6,750ms | 3,000ms | 통과 |
| 60초 | 14,250ms | 3,000ms | 통과 |

경계는 4개가 되고, `moveTimelineBoundary`는 이미 N구간 일반화가 끝나 있어 **무변경**이다.

### 2.3 재생·대비 규칙

Day1 D1을 그대로 승계한다 — **재생 중인 패널 1개, 나머지는 자기 트림-인 프레임에 정지 +
`grayscale(1)`.** 동시 디코드가 1개로 유지되어 디코드 비용이 Day1 수준에 머무는 것이
이 규칙의 진짜 이유다(`day1-render-speed.analysis.md` §1: 디코드가 렌더 시간의 68.5%).

**Q2 확정(2026-08-24)**: 이 규칙으로 간다. 검토했던 대안과 기각 사유를 남긴다.

- **(b) 누적 점등** — 지나간 패널은 컬러 정지로 남기고 아직 안 온 패널만 흑백. 디코드
  비용은 (a)와 동일하다. 기각 사유는 비용이 아니라 일관성 — Day1의 "비활성 = 흑백"
  규칙과 어긋나 두 템플릿의 대비 문법이 달라진다. 필요해지면 후속 사이클에서 옵션으로.
- **(c) 4개 동시 재생** — 동시 디코드 4개. 회귀식(`5.35ms + 2.83ms × Mpx`/프레임)을
  네 번 물면 15초/30fps/9:16에서 디코드만 약 6초 늘어 렌더가 20초대가 된다. 기각.

- **패널을 배열이 아니라 이름 키로 둔다.** `Day1PanelKey`를
  `'panelA'|'panelB'|'panelC'|'panelD'`로 넓히면 기존 명령 15종이 코드 변경 없이
  두 템플릿을 동시에 서비스한다. 그리고 `DAY1_PANEL_SECTION`(패널 → 구간 인덱스)이
  `{panelA:0, panelB:1, panelC:2, panelD:3}` 하나로 **두 템플릿 모두 성립**한다.
- **라벨 문구**: `copy.day1Labels`에 `c`/`d`를 optional로 추가. optional이므로 저장된
  Day1 문서는 손대지 않아도 파싱되고 마이그레이션이 없다 — `endCard.mode`가
  `.default('banner')`로 마이그레이션을 없앤 것과 같은 수법.
- **기본값 `DEFAULT_DAY1_QUAD_SETTINGS`**: Day1 기본값을 복사하고 **한 곳만** 바꾼다.
  - `labelStyle.fontSize`: 72 → **44**. 셀 폭이 1080 → 537로 반이 되므로 72px는 셀을 넘는다.
  - 패널 `transform.fit`: **`contain` 유지** (Q4 확정). `DEFAULT_DAY1_PANEL_TRANSFORM`을
    그대로 재사용하므로 새 상수가 필요 없다.

```
Day1QuadComposition.tsx      신규 — Day1Composition과 같은 골격, 구간 5개
  └ day1/QuadFrame.tsx       신규 — 셀 4개 + 십자 분할선 2개
      └ day1/Panel.tsx       추출 — SplitFrame.tsx 내부 Panel을 파일로 이동
  └ day1/EndCardScene.tsx    재사용 (무변경)
  └ shared/AudioLayer.tsx    재사용 (무변경)
```

`SplitFrame.tsx`는 추출한 `Panel`을 import하는 형태로만 바뀐다 — 마크업·스타일·필터는
한 글자도 건드리지 않는다. Day1의 SC2(흑백이 MP4까지 살아남는지)·SC4(분할선 픽셀 색)
E2E가 그 이동의 검증 장치가 된다.

`EditorSnapshot`에 `{template: 'day1-quad'; props: Day1QuadProps}` arm을 추가하고,
`buildEditorSnapshot()`에 분기 하나를 더한다 — conventions §3.1이 말한 "두 개의 arm".

### 2.6 도메인 (신규 순수 함수 3개)

| 함수 | 파일 | 책임 |
|---|---|---|
| `quadLayout(ratio, lineWidthPx)` | `domain/day1/layout.ts` | 셀 4개 + 분할선 2개 사각형 |
| `activePanelForQuadSection(index)` | `domain/day1/playback.ts` | 0..3 → `'a'..'d'`, 4 → null |
| `day1QuadSectionDurations(preset)` | `domain/day1/playback.ts` | 3초 엔드카드 + 4등분 |

`sourceProxy.ts`(crop 계획)는 박스와 transform만 받으므로 **무변경으로 4셀에 그대로 적용**된다.

### 2.7 UI

| 화면 | 변경 |
|---|---|
| 템플릿 선택기 | 4번째 버튼 `Day1 4분할`. 파괴적 전환 경고문에 항목 추가 |
| 애셋 패널 | 영상 슬롯 2 → 4 (`PANELS` 리스트를 템플릿에서 받음) |
| 인스펙터 | 패널 섹션 4개(트림·프레이밍·프리뷰). 분할선·라벨 스타일·엔드카드는 그대로 1세트 |

인스펙터 세로 길이가 늘어나는 것이 유일한 UX 부담이다. day1-video 사이클에서 인스펙터

### 2.8 렌더·프록시

- `panelProxies.ts`의 패널 리스트를 템플릿에서 받도록 일반화. 슬롯 상한이 패널×규격이므로
  **4패널 × 3규격 = 최대 12슬롯**, 측정된 4.3MB/슬롯 기준 약 **52MB**. Q9에서 상한 정책 확인.
- 프리플라이트·Batch·파일명·자동저장·JSON 내보내기는 전부 템플릿 무관 경로라 무변경.

## 7. Risks

| # | 리스크 | 완화 |
|---|---|---|
| R1 | **합성 비용 — 이번 사이클 1번 리스크.** Q4가 `contain` 기본으로 확정됐으므로 한 프레임의 video 요소가 최대 8개(패널 4 + 블러 배경 4)다. `createFrame`은 렌더 시간의 25.2%이고 DOM 수에 비례한다 | **M0을 `contain` 4패널(최악 구성)로 측정**한다. 1.5배를 넘으면 Q13 정책에 따라 판단하고, 축퇴안은 "정지 패널의 블러 배경을 PNG 1장으로 사전 추출"이다 (정지 패널의 배경은 어차피 프레임 1장이다) |
| R2 | **정지 패널이 매 프레임 디코드될 수 있다.** `Freeze`가 정말 1회 디코드인지 4개에서도 성립하는지는 측정한 적이 없다 | M0에서 `waitForReady`로 확인. 성립하지 않으면 정지 프레임을 PNG로 사전 추출 |
| R3 | 라벨 기본 72px가 537px 셀을 넘는다 | 기본값 44px로 하향(§2.4), M4 E2E에서 4언어 최장 문구 확인 |
| R4 | 15초 프리셋에서 패널당 3초는 짧다 | 스키마는 통과한다. 기본 프리셋을 30초로 둘지 Q8 |
| R5 | 프록시 메모리 최대 52MB | 슬롯 상한 정책 Q9 |
| R6 | `Panel` 추출이 Day1에 회귀를 만든다 | 순수 이동으로 제한. Day1 E2E(흑백·분할선 픽셀)가 게이트 |
| R7 | 인스펙터가 세로로 길어진다 | 기존 `InspectorSection` 접기 재사용 |
