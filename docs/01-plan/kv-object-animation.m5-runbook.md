## 2. 본 렌더 — 이펙트 on/off 두 벌

같은 프로젝트로 **두 번 렌더**한다. off 렌더가 SC1(영역 밖 무변화)·SC6(이펙트
없는 프로젝트 비트 동일)·SC5(비용)의 기준선이다.

1. 키비주얼 루핑 템플릿, 소다전설 3장 업로드, 15초 · 60fps · Standard.
   카메라 설정은 기본값 그대로.
2. **이펙트 on 렌더**: 각 KV 슬롯에 "파티클 추가" + "글로우 추가" — **기본값
   그대로**(M4 실측치: 밀도 0.2 · 속도 0.4 · 8px · 주기 1300ms). 오버레이
   드래그로 글로우 중심만 각 원화의 광원 위에 놓는다(파티클 영역은 기본 배치
   유지 — SC1 판정이 기본 영역 기준으로 계산돼 있다). MP4 렌더, **렌더 소요
   시간을 기록**(화면 진행 표시로 충분).
3. **이펙트 off 렌더**: 같은 프로젝트에서 이펙트를 전부 삭제하고 MP4 렌더,
   소요 시간 기록.
4. 두 MP4와 두 소요 시간을 Claude 세션에 업로드/전달하면 프레임 실측으로
   SC1~SC7을 판정한다.

육안 검수 포인트 (M4 기본값의 체감 판정):
- 불티가 "숨은 그림"이 아니라 보이는가 — 밀도 0.2(동시 ~10개)가 원화 위에서
  읽히는가. 과하면 레퍼런스(모닥불 원화 10~13개)보다 밀한 것이다.
- 상승 속도 0.4가 "불티" 로 읽히는가 (레퍼런스의 표류 반딧불 ↔ 고속 불티
  사이 지점이다).
- 글로우 펄스 1.3초가 자연스러운가, 세기 0.6이 원화를 태우지 않는가.

## 3. 성능 게이트 (D-05 — 이 사이클의 확정 지점)

컨테이너 참고치: 카메라 정지에서 이펙트 비용 ≈0ms/프레임, transform 하
≈19~25ms/프레임 (자체 래스터라이저, 1회 측정 상한). 네이티브 경로가 판정이다:

- §2의 on/off 소요 시간 차이가 **전체의 5% 이내**(카메라 사이클의 NFR-R02와
  같은 기준) → 통과, D-05의 게이트 수치로 기록.
- 벗어나면 원인 분해가 필요하다 — 파티클 수(밀도)·글로우 반경을 반으로 줄인
  렌더로 어느 쪽이 지배 비용인지 가르고, 다음 커밋에서 다룬다.

## 4. (선택) 네이티브 경로 하네스 재실행

M0 하네스를 실기기 Chrome으로 돌려 두 래스터화 경로의 일치를 수치로 닫는다:

```bash
npm run dev -- --host 127.0.0.1 --port 4173   # 별도 셸
KV_OBJ_M0_CHROME="/path/to/chrome" node artifacts/kv-obj-m0/run.mjs
node artifacts/kv-obj-m0/verify.mjs            # 5/5 PASS 기대
```

픽스처(out/tex.png)가 없으면 m0-canvas-spike §4의 ffmpeg 한 줄로 생성.
`nativeHtmlInCanvas: true`로 찍히면 네이티브 경로를 실제로 측정한 것이다.
