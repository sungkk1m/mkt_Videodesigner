| **Core Value** | 성과 검증된 비교 포맷을 외부 편집 도구 없이 반복 생산한다. 동시에 `template` 판별자가 들어가면서 이후 UA 포맷(리뷰 인용, 랭킹 자랑 등)을 스키마 재설계 없이 얹을 수 있는 기반이 생긴다. |

## 1. Overview

### 1.1 Purpose

레퍼런스 GIF와 같은 상하/좌우 분할 비교 영상을 편집기 안에서 만든다. 부수적으로, 앞으로 UA 포맷을 늘릴 수 있도록 프로젝트 스키마에 템플릿 개념을 도입한다.

### 1.2 Background

- 레퍼런스: 640×640 GIF. 가로형 영상 2개를 위아래로 쌓고, 가운데 하늘색 분할선, 각 패널에 굵은 흰 글씨 + 검은 외곽선으로 `DAY 1` / `DAY 30` 라벨.
- 현재 스키마는 `scenes`가 3튜플로 고정되어 있고([schema.ts:191](../../../../src/domain/editor/schema.ts:191)) `source`가 단일 영상이다([schema.ts:192](../../../../src/domain/editor/schema.ts:192)). Day1은 이 두 전제를 모두 벗어난다.
- bannerdesigner는 이미 템플릿 10종을 드롭다운으로 전환한다. 같은 개념을 영상 쪽에 들여온다.

### 1.3 Confirmed Product Decisions

착수 전 사용자 확인을 거친 항목이다. Design 단계에서 뒤집지 않는다.

| # | 결정 | 근거 |
|---|------|------|
| D1 | **활성 패널만 재생, 비활성은 첫 프레임 정지 + 흑백** | "전에는 이랬는데 지금은" 대비가 가장 명확하고, 동시 디코딩이 1개로 유지되어 렌더 비용이 현재 수준에 머문다 |
| D2 | **컬러 전환 시점은 타임라인 경계 드래그**, 기본값은 분할 구간의 중간 | 기존 3장면 경계 드래그와 동일한 조작감이라 추가 학습이 없다 |
| D3 | **템플릿 선택기로 기존 3장면과 공존** | 검증 완료된 Hook 분석·CTA·다국어 자막 경로를 버리지 않는다 |
| D4 | **엔드카드 = 완성 배너 PNG(배경) + 앱아이콘 PNG(오버레이)** | 앱아이콘을 별도 레이어로 두어야 축소·이동까지 제약 없이 애니메이션할 수 있다 |

| D6 | **패널 라벨은 패널별 + 4언어 분기** | 기존 카피 패널의 4언어 구조를 그대로 쓴다 |
| D7 | **오디오는 활성 영상의 원본 사운드를 따라간다** | 전환 시 자연스럽게 넘어가고 기존 원본볼륨·BGM·더킹 설정을 계승한다 |
| D8 | **16:9 엔드카드는 bannerdesigner에 16:9 규격을 먼저 추가해 해결** | 아래 §2.3 참고 |
| D14 | **Day1에서는 Hook 탭과 함께 카피 탭도 숨긴다** | Do module-5에서 Hook 숨김만 승인받았으나, 카피 패널의 필드(헤드라인·CTA·장면 자막)는 전부 3장면 개념이고 Day1의 문구는 인스펙터의 패널 라벨 2개뿐이다. 남겨두면 효과 없는 입력칸만 노출된다. Check 단계에서 사후 승인 (2026-07-30) |
| D15 | **16:9 엔드카드도 자동 배치로 완성한다** | Check 단계 사용자 결정(2026-07-30, "Gap 전부 수정")에 따라 bannerdesigner에 app-badge 16:9 레이아웃을 추가하고 좌표 상수를 붙였다. D8/§2.3의 선행 조건이 해소됐다 |

## 2. Scope

### 2.1 In Scope

**템플릿 기반**
- 프로젝트 스키마에 `template: 'three-scene' | 'day1'` 판별자 추가, 스키마 버전 v1 → v2
- v1 프로젝트를 읽을 때 `template: 'three-scene'`으로 자동 승격하는 마이그레이션
- 헤더 템플릿 선택기

**Day1 분할 구간**
- 영상 2개 업로드 (둘 다 필수)
- 규격별 분할 레이아웃

  | 출력 | 분할 | 패널 크기 | 재생 순서 |
  |------|------|-----------|-----------|
  | 1080×1080 (1:1) | 상하 | 1080×540 (2:1) | 위 → 아래 |
  | 1920×1080 (16:9) | 좌우 | 960×1080 (0.89:1) | 왼쪽 → 오른쪽 |
  | 1080×1920 (9:16) | 상하 | 1080×960 (1.125:1) | 위 → 아래 |

- 활성 패널 재생 / 비활성 패널 첫 프레임 정지 + `grayscale(1)`
- 컬러 전환 경계 드래그 (기본 중간)
- 패널별 Cover 프레이밍 (Scale·X·Y), 규격별 override
- 분할선: 두께 조절, 색상 기본 회색, 컬러 피커 + **스포이트(EyeDropper API)**
- 패널 라벨: 패널별 문구, 4언어 분기, 기본 스타일은 GIF 기준(굵은 흰 글씨 + 검은 외곽선), 위치·크기·색 조절

**엔드카드**
- 완성 배너 PNG 업로드 (배경, Cover)
- 앱아이콘 PNG 업로드 (오버레이). 규격별 **고정 좌표에 자동 배치**, 수동 미세조정 가능

  bannerdesigner app-badge CSS에서 추출한 상수다. 아이콘 크기를 바꾸는 사용자 컨트롤이 없어 결정적이다.

  | 규격 | x | y | w | h | radius |
  |------|---|---|---|---|--------|
  | 1:1 | 26.11% | 34.72% | 47.69% | 47.69% | 8.89% |
  | 9:16 | 18.52% | 42.71% | 62.96% | 35.42% | 11.11% |
  | 16:9 | 57.08% | 22.04% | 33.33% | 59.26% | 6.51% |

  > 16:9 행은 bannerdesigner v1.18(2026-07-30)이 app-badge 1920×1080 레이아웃을
  > 추가하면서 확정됐다 (D15). CSS 원본은 `top 238 / left 1096 / 640×640 / radius 125`.

- 앱아이콘 애니메이션 프리셋 (팝인 / 펄스 / 글로우)
- 카드 전체 모션 (Ken Burns, 페이드 인)

**통합**
- 렌더·Batch·자동저장·JSON 내보내기는 기존 경로 재사용

| SC3 | 기존 3장면 프로젝트가 회귀 없이 열리고 렌더된다 | 기존 E2E 17개 통과 + v1 JSON 가져오기 테스트 |
| SC4 | 분할선 색이 지정한 값으로 렌더된다 | 렌더 프레임의 분할선 좌표 픽셀 색상 검사 |
| SC5 | 엔드카드 앱아이콘이 고정 좌표에 정확히 겹친다 | 배너 PNG의 아이콘 영역과 오버레이 위치 오차 ≤ 2px |
| SC6 | 유닛·E2E 전부 통과, 타입체크·빌드 통과 | `npm test && npm run build && npm run test:e2e` |

### 4.2 Quality Criteria

- Day1 도메인 로직(분할 기하, 전환 시점, 패널 매핑)은 순수 함수로 분리하고 유닛 테스트를 붙인다.
- 스키마 마이그레이션은 v1 픽스처를 두고 왕복 테스트한다.
- 기존 `data-testid`는 유지하고 Day1용은 새로 추가한다.

### 4.3 Performance Gate

Design 착수 전 **2영상 렌더 스파이크**를 먼저 돌린다. 기존 `npm run benchmark:render` 하네스를 재사용해 "재생 1개 + 정지 1개" 구성의 15초 9:16 렌더 시간을 실측하고, 3장면 기준선과 비교한다. 1.5배를 넘으면 정지 프레임을 `<Freeze>` 대신 사전 추출 이미지로 바꾸는 설계를 택한다.

## 5. Risks and Mitigation

| 위험 | 영향 | 대응 |
|------|------|------|
| 스키마 v1→v2 마이그레이션이 기존 저장 프로젝트를 깨뜨림 | 높음 | v1 픽스처 왕복 테스트를 먼저 작성. 마이그레이션 실패 시 원본을 보존하고 사용자에게 알림 |
| 정지 프레임도 디코딩이 필요해 렌더가 느려짐 | 중간 | §4.3 성능 게이트에서 실측 후 설계 분기 |
| 완성본 PNG 위 아이콘 오버레이가 어긋나 잔상이 보임 | 중간 | 좌표는 CSS에서 추출한 상수를 쓰고, FR-D13 수동 미세조정을 제공. SC5로 검증 |
| bannerdesigner app-badge 레이아웃이 바뀌면 좌표 상수가 깨짐 | 중간 | 좌표를 한 파일에 상수로 모으고 출처를 주석에 남긴다. 어긋나면 수동 조정으로 복구 가능 |
| EyeDropper API가 프리뷰 밖 화면까지 집는다 | 낮음 | Chrome 기본 동작이다. 안내 문구로 설명하고 컬러 피커를 병행 제공 |
| Day1이 3장면 코드를 오염시켜 회귀 발생 | 중간 | 판별자로 컴포지션·인스펙터를 분리하고, 매 모듈 종료마다 기존 E2E 전량 실행 |
